## 3. 新数据流：准备事实，再生成完整回答

### 3.1 仅接入自主页面 Agent

范围为现有 `mode="agent", library_mode=True` 的自主论文问答。固定 RAG、旧非自主 Agent、普通 CLI 的三次请求策略保持原状。通用知识或纯对话无需论文事实时，保留现有直接回答能力，不强制先抽取事实。

当前 [run_autonomous](D:/course/paper-research-assistant/paper_assistant/agent.py:491) 一旦收到 AnswerAction 就直接 publish。本批将准备发布论文结论的终结点改为：

```text
原问题 + 当前已读证据
        ↓ 当前自主决策：调用工具，或产出内部事实准备动作
题目相关的原子事实 + 原句 + 来源 + 所问覆盖／缺口
        ├─ 核心缺口仍需取证 → 下一步现有 search／read_context
        └─ 可以完成回答，或只能说明剩余缺口
                  ↓ 单独一次最终生成
            完整 AnswerDraft
                  ↓ 现有引用与来源发布流程
```

不是先生成一份完整答案，再提取、审核和重写它。原来的终端决策改为事实准备，只有最终组织回答是新增调用；先前回答和历史模型结论不作为已核实事实输入。

### 3.2 最小内部事实准备协议

在现有动作解析处增加仅供自主论文路径使用的 `prepare_answer` 动作，承载以下内容：

- `facts`：复用 Claim 的主张、citation_ids 和 evidence_quotes；事实来自本轮实际可见原文，准备阶段只写原文支持的事实，不写额外分析或世界知识。
- `answerable`：当前证据是否足以回答核心所问，由模型声明，程序用于决定是否进入最终表达；不称为已经证明答案正确。
- `missing_information`：所问尚缺什么，或相关片段哪一处不能确定。可回答核心时仍可说明局部不确定性，不能因不必要的符号展开不清而把整个问题判成不可回答。

不为主张增加固定的实体、关系分类体系，不新增题型模型。事实和引句需要多个原文片段支持时分别保留来源，不拼接成伪造原句。

准备提示直接采用 RAGFlow 的原子、忠实、主体明确及原句绑定条款。事实数量由完成当前问题所需内容决定，沿用现有上下文与输出预算，不规定必须抽取几条来凑格式，也不提取整个论文的全部事实。

### 3.3 缺口必须影响实际动作

- 现有原文能够回答核心所问时，进入最终表达；不因还有相关背景未读而继续搜索。
- 仍缺必要来源、定义、限定或比较条件，且有明确可执行方向与剩余额度时，把准备动作及缺口留在现有 action_steps／executed_actions 中，返回当前工具循环，由下一步 search／read_context 解决该缺口。
- 新证据进入后可以再次准备事实；每次准备都占现有自主决策步，不能成为不计步的额外循环。
- 已到步骤或取证上限，或没有可靠的继续取证方向时，用已取得事实和具体缺口完成回答。保留现有 answered／Unanswerable 含义，不新建产品终态，不把未知写成否定结论。

最终表达不能再调用搜索工具，不能在该阶段重新启动探索。上限收尾同样明确依据当前材料作答；准备材料为空时允许以具体缺口完成回答，不为满足非空 claims 编造事实。

### 3.4 最终表达真正消费前一步材料

最终生成使用原问题、已有输出要求、准备事实、对应原句、必要的来源／章节限定和具体缺口。通过现有消息及 context 构建能力保留这些原文来源；不把整段无关搜索历史或全部论文材料再次作为自由综合的素材。

最终回答遵循：

- 每项论文事实均以准备材料中的主体、关系、数值和限定为依据；原句仍随事实提供，不能只把模型提炼的 claim 当成权威。
- 可以为流畅表达合并句子，但不能自行创造新的类别分组、因果关系、统计结论或排除性判断。
- 用户要求分析时保留分析能力，明确区分原文事实与推论；推论的材料前提及必要条件应有支持，不能用 analysis 标签绕过证据要求。
- 核心答案清楚放在前面，解释按所问需要展开；附加但正确的内容不因篇幅长自动判错，重复背景可精简。
- 最终仍一次生成完整 AnswerDraft。若请求了 direct_answer，按已有协议一并生成；不从参考答案挑句，不为该字段另加调用，不通过复制字段决定产品是否合格。

最终继续走 [publish](D:/course/paper-research-assistant/paper_assistant/agent.py:314) 的既有引用、来源检查与保存路径。事实准备与最终回答的消息、原始响应、阶段和用量保存在现有 action_steps 及账本中，不另建审核或报告系统。

## 4. 符号问题按局部不确定性处理

本批不根据已知失败题硬编码 `ď`、`K3` 等字符串，也不统一把相似符号替换成 `≤`、`⊑` 或 `=`。

事实准备遇到原文关系无法可靠确定时：

1. 保留原始引句与来源，不把不确定符号改写成确定关系。
2. 将当前材料无法确认的部分写入已有缺口说明；可读的来源、筛选条件和其他事实继续正常回答。
3. 原问题确实需要该关系时，可用现有阅读工具补足上下文。相同解析文本仍不能确定时，明确局限，不重复读同一材料直到额度耗尽，也不声称已经视觉核对原 PDF。

验证人员事后可查看本地已有 PDF 的对应页，区分源文本识别异常与答案错述；这只是评价依据，不向模型或工具传入正确位置、原图判读结论或参考答案。运行时不新增 VLM／OCR 调用，不承诺本批修复所有公式。
