## 2. 准备规则的最小调整

沿用 [FACT_PREPARATION_RULES](D:/course/paper-research-assistant/paper_assistant/agent_prompt.py:150)、已有 Claim／EvidenceQuote 及 `facts / answerable / missing_information`。保留 2.14 从本地 RAGFlow 采用的主体明确、原子、忠实、原句绑定与模态保留约定，只针对已见的相关分支遗漏澄清职责。

### 2.1 原子化拆分保留所问关系

- 先整理直接回答原问题的事实及必要条件，再整理确有需要的背景。
- 原句中的 A 或 B、并列来源、并列条件、例外和适用范围，凡影响原问答案的都应保留。可以拆成多条原子事实，不因“每条一个事实”只留下其中一个相关分支。
- 保留 can、may、only if、否定和归属等限定。原文列出可用构建方式时，不能加强成作者全部实际执行了这些方式。
- 不要求抽取整篇论文或所有背景，不设固定事实数量、来源数量或题型分类体系。
- 规则使用通用关系表达，不在生产提示中硬编码 MonaLog、WordNet、manually、正确量词链或该题的证据位置。

### 2.2 answerable 按原问判断

`answerable` 判断已有事实能否支持原问所需回答；`missing_information` 只说明影响该回答的必要缺口或局部不确定性。

原问没有要求时，不把正式算法、完整库存、精确数量、额外实验细节等升级为必需信息。已经有来源及筛选条件时，应先回答这些已支持内容；补充局限不能泛化为没有选择依据，也不能让附加但未被询问的信息遮住核心回答。

本批继续使用已有协议和生成阶段，不增加覆盖评分字段、同义缺口字段、自审动作、语义校验器或额外审核调用。

### 5.3 评价内容与实际成本

按原问题、实际输入和原文含义评价：

- 必要来源、替代路径、适用条件及 can/or/only if 等限定是否完整保留。允许同义表达，不按 manually 等关键词计分，也不要求整篇背景全部出现。
- 核心事实是否在准备阶段遗漏；准备已保留而最终未表达的，另记为最终覆盖问题。对模态或关系的无依据加强，作为独立忠实性问题说明。
- `=`、`≤`、`⊥` 等关系是否继续正确；等价的 Unicode／LaTeX 表达可以通过。原问不要求的关系链可以省略，若未输出就如实说明该链本轮未覆盖。

评价者说明为 AI 辅助原文对照，不冒充独立人工准确率，不参考 direct_answer／F1，不把字段解析或引用通过当成语义通过。
