## 1. 目标与选型

本任务处理实际输入链：恢复论文阅读顺序、正文、公式和表格，减少缺少语义的独立碎片，并让检索命中能带回完整的必要上下文。2.6 已完成的离线映射继续使用，但映射率不作为分块质量或问答准确率的替代指标。

采用一条主线：

**真实 PDF → MinerU Standard 结构解析 → 正文／公式／表格／图片分类与来源位置 → 父段落与子块 → 混合检索、现有重排 → 父上下文展开 → 可回查的实际子证据 → 当前固定 RAG／五步 Agent。**

| 部分 | 本轮选择及依据 |
|---|---|
| PDF 主解析 | 当前选择 MinerU Standard，使用 Torch＋LMDeploy CUDA；保留正文、公式、表格及结构定位，关闭额外图片／图表语义分析并保留图片资产。按用户要求调整默认档位，已有 Advanced 实施及效果记录保留。[官方档位](https://opendatalab.github.io/MinerU/usage/tiers/) |
| 结构与来源 | 使用解析器的结构 JSON 和图片资产，保留真实页码、块、页面尺寸及 bbox；不能只保存 Markdown。当前官方 4.0 输出与旧版不同，实施时按实际安装版本的公开契约接入，不硬套旧 `pdf_info`／`para_blocks` 字段。[输出说明](https://opendatalab.github.io/MinerU/reference/output_files/) |
| 结构分块 | 借鉴 Docling HybridChunker：先按结构组织，再拆超长块、合并同结构范围的短块，保留标题与图表关联。[官方说明](https://docling-project.github.io/docling/concepts/chunking/) |
| 检索与阅读 | 借鉴父子块：索引较小子块，命中后取回较大父上下文。复用现有向量／BM25／重排，不迁移整个 RAG 框架。[参考实现](https://developers.llamaindex.ai/python/framework/integrations/retrievers/auto_merging_retriever/) |

只接入一个主解析器，不同时部署 MinerU、Docling、GROBID 做逐页投票。Docling 和父子块框架用于参考组织方式，不要求作为额外运行依赖。效果优先意味着允许使用结构模型、视觉解析和较充分上下文；不意味着将所有论文交给另一个模型重复审核。

## 3. A：完整解析与结构分块

### 3.1 主解析器与内容恢复

使用 MinerU Standard 的完整文档解析，明确处理全部 PDF 页，使用正常结构结果及资产保存接口。避免误用默认只读部分页的阅读型入口。实际部署版本、档位和解析配置随已有版本记录保存，不增加另一套清单或哈希。

保留标题层级、正文顺序、段落、列表、公式、表格、图注和图片区域，按内容类型组织：

- 正文：恢复双栏的阅读顺序、同段跨块／跨页的延续，修正断词；图中标签不混入正文续句。
- 公式：保留识别出的 LaTeX、公式编号、所在区域及邻近解释。对新结构输出按实际提取内容处理，不能继续机械套用旧数学字体拒绝规则；也不能把无法恢复的公式从 QASPER 答案中补回。
- 表格：保留行列结构、标题、单位和脚注；检索文本保留行及列标题的对应，超长表按完整行拆分并重复必要表头，不把数值单独切成无列名的碎块。
- 图片：保留原图区域、图注和所属章节，独立于正文；图中短标签不作为普通正文小块散落索引。图注或可定位的区域文本作为检索入口，原图保留供图文阅读；本轮文本子集成绩不宣称覆盖图像理解能力。
- 页眉、页脚、参考文献：保留原始结构及定位，不默认与普通正文混合进入正文检索集合。论文自身标题、摘要与引用表的来源角色保持明确。

优先使用主解析器现有结构和公式能力。不默认增加第二套 OCR、全文改写模型或“解析后再让 VLM 校对一遍”的流程。若仍有具体内容未恢复，保留其实际状态和原图位置，按失败点继续修复。

### 3.2 分离来源单元、父上下文与检索子块

来源单元承载真实 PDF 位置；父内容组织完整段落或同章节相邻段落；子块是向量／BM25 的检索单位。不能因为要保留坐标，就让每个短版面块都独立成为检索单位。

先按标题、段落、列表和图表结构形成父内容。正文父内容可以跨页，跨页延续不能被页眉或图文打断。短段落只在同一结构范围且正文连续时合并，不为凑长度跨章节或混入图表。公式与其解释、表格与表题保持关联。

首轮固定起点为：子块目标上限 512 token、正文父上下文目标上限 1536 token。使用与所用模型兼容的本地 tokenizer 计量；这两个数是初始配置，不是已经证实的最优值。本轮不同时扫描多套长度。

完整短段落不再按固定字符数硬切；超长正文优先按句界拆分，必要时保留相邻一句上下文。长列表按完整条目处理，公式和表格按其结构处理，不把公式字符串、表格单元随意截断。超长完整结构超出模型输入能力时，按该结构的自然组成拆开。

### 3.3 来源与版本的落地方式

采用“子块可引用、父内容供阅读”的方案：子块尽量限制在单页，但可组合该页多个正文来源块；跨页父内容由多条真实子证据组成，沿用现有引用中的单页 `pdf_page`。

父子记录包含 `parent_id`、章节路径、内容类型及有序 `source_spans`。来源范围记录源块、真实页码、bbox、可用的源字符范围，以及其在存储文本中的范围；视觉转录使用实际区域来源，不编造与旧 PDF 文本相等的字符切片。不同栏和不同页不合成一个虚构大矩形。

SQLite 保存父文本、关系和来源，Qdrant 仍只索引子块。相应更新现有 loader／存储的单切片假设；老版本按原格式读取。不能用虚构 segment、伪造行号或放宽旧约束蒙混新内容。

同一 PDF 切换解析／分块方案时生成新的实际解析版本；相同方案的重复导入继续沿用现有复用语义。尤其要修正当前“PDF 相同就直接复用最近旧分块”的入口行为，不用随机更换论文 ID 绕过。保留原 PDF 身份及旧版本，不清库、不额外添加哈希机制。

## 4. B：父上下文、引用与评测接通

首轮实施与记录见 [2.7 B 专项规划](2.7-B-parent-context-mapping-plan.md)，已根据 A 的实际输出接通来源 registry、预算投影及多来源 mapper。B 首轮只复用新版本，两个相关离线方法通过后已计算一次映射，正式 train20 旧绑定保留。后续批次已按 [B 后续规划](2.7-B2-evidence-attribution-plan.md)修正已证明的接缝、标题、段落归属及参考文献分类；本节保留首轮架构目标，后续具体范围与映射口径以该规划为准，不重复首轮或提前执行 C。

### 4.1 检索命中后的上下文

沿用现有向量＋BM25、RRF 和重排，子块命中后按父内容归并，取回必要的关联子块。使用实际父子关系替代只靠“同页、同 segment 邻块”猜测续文，避免多个命中重复展示同一父段落。

父上下文初始总预算设为 8192 token，并受实际生成模型剩余输入窗口约束；为现有输出预算留出空间。更新当前 8000 字符、最多 8 条上下文的统一截取位置，使跨块父段落不会刚恢复又被旧上限截断。新增上下文来自已存储实际来源；展示时仍按可引用的子证据标识分段，不把父文本冒用为某个子块的原文。

固定 RAG 和 Agent 使用同样的来源恢复与上下文预算。Agent 仍为最多 5 次自主决策，生成模型、embedding、重排模型和既有一次格式修复策略保持当前设置；本任务不同时优化轮数或模型选择。

### 4.2 引用回查

模型输出引用实际子证据 ID，不输出虚构父引用。父内容跨页时，展示对应的多个页内证据及各自区域；引用回查和 UI 读取实际 `source_spans`。

`context.py` 等投影不能丢弃父子关系和来源信息；`citations.py` 仍基于实际存储证据判定展示／引用一致。视觉转录与图像来源保持明确，不将生成的说明伪装成 PDF 的逐字正文。复用现有引用流程，不另叠加语义裁判或第二套审核链。

### 4.3 QASPER 对应与计分

2.6 的文本归一、跨块对齐继续使用，增加对新 `source_spans` 和实际子证据的消费。映射范围仍为全部原始段落，标准答案和证据标签只在事后评分使用；本任务测真实 PDF 路径，不用官方正文替换解析结果。

区分三个事实：完整对应、部分正文已对应但有缺口、来源不在官方正文范围／无法定位。直接在现有原因与统计中说明，避免将它们混成“PDF 大部分没读到”；不新建评分前审核工具。不能仅凭 chunk 完整映射比例评价质量，也不能把引用中的未映射内容丢掉后计分。

Answer F1 与 Evidence F1 算法和参考答案集合保持原口径。Evidence F1 仍保留 null 及实际可评分母，并使用两模式共同可评题目比较；缺口不能通过删除题目或替换抽样解决。页眉等附属内容分离不等于自动提高答案分数。
