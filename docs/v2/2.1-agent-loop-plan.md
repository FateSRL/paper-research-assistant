## 1. 目标与边界

将统一页面中的 Agent 改为：**模型选择检索或回答 → 程序执行工具 → 返回观察 → 模型决定下一步**。第一步就交给模型选择；前置计划仅供参考，不自动执行全部子查询。

- 交付入口是页面实际使用的 `d9_runtime.run_question(library_mode=True, mode="agent")`，覆盖首问和追问。
- 首版仅开放 `search / answer` 两类动作；复用现有混合检索、重排、证据合并、规则式原文展开、回答与引用检查。模型主动 `read` 工具后移，不纳入本次。
- 固定 RAG、非页面 CLI 和旧批量对照保持现有用途；新循环由页面 Agent 显式启用，核心默认行为兼容旧调用。不增加页面开关。
- 不实施 2.2 的批量评测改造、2.3 的 QASPER 接入或 2.5 的入库提速；本次不运行真实效果实验。用户指定先推进 2.1，不把其他章节变成本任务的前置工程。
- 使用现有普通函数和动作结构，不引入 LangGraph、其他 Agent 框架、多 Agent、通用工具注册中心或独立计划管理器。
- 不增加哈希、源码快照、manifest、审计、额外校验层、独立验证报告；继续复用现有论文范围约束和引用检查。

## 2. 必须实现的行为

### 2.1 模型决定实际动作

新增循环中的 `search` 动作表达实际查询和 `selected_versions`；只允许选择用户已选论文及解析版本的非空子集。简短取证目标可复用现有缺失信息字段，无须输出长篇推理。

`answer` 直接携带现有回答结构，走现有发布与引用检查。保持当前论文事实、模型知识和分析的区分规则，不要求所有问题先检索，也不允许为空证据编造引用。

保留现有前置理解、指代补全和澄清；需要澄清时直接结束该次请求，不进入循环。已有 `planned_queries` 只作为可修改的建议，模型可调整查询、切换已选论文子集、跳过建议或提前回答。

### 2.2 五步上限与收尾

- 最多 **5 次自主动作决策**。一次正常决策占一步；选择检索则执行并返回观察，选择有效回答则立即结束。
- 第 5 步直接回答时不再额外收尾；第 5 步仍选择检索时，执行后最多增加一次只允许回答的收尾决策，明确已有证据与剩余缺口。
- 独立前置理解、网络重试、格式／引用修复不计为新的自主步数，仍按现有共享限制和真实请求统计记录。最终修复不能重新开放检索，也不能重置五步计数。
- 页面已有 `max_attempts=None` 的交互策略，不需要放宽全局 `ChatPolicy` 的旧三次请求默认或修改冻结配置。自主步数限制独立于 SDK／HTTP 请求数；不能只把请求上限改成 5 就宣称实现了五轮 Agent。
- 启用参数保持简单，例如核心接受可选步数参数，旧调用默认不开启，页面 Agent 传入 5；不增加新的环境变量或配置体系。

### 2.3 每次观察与证据累计

模型每轮收到原始完整问题、已选论文信息、建议查询、已执行动作及结果、当前可见证据和剩余步数。复用现有消息与结果结构，无须传入全部论文全文或额外建立“记忆服务”。

每次检索继续使用现有 top 5；累计证据复用现有多查询合并能力，保持最多 8 条完整片段／8000 字符。最终可引用 ID 仅来自当次实际展示的上下文，不能把历史上已被截掉的证据 ID 继续作为可用引用。

原问题的摘要／来源限制必须约束每次新查询，不能因模型改写查询而丢失。模型可在已选版本之间调整范围；相同查询用于不同论文是合法取证，不应被误判为重复。

无命中或无新增展示证据时，将实际结果反馈给模型；有剩余步数时允许它换查询或论文继续。重复的“同查询＋同版本范围”沿用现有去重思路，不重复发 embedding，但该次模型决策仍占一步，并返回重复观察。不要继续沿用“一次补查后只能回答”的阶段限制。

检索失败、格式错误及资源失败沿用现有处理和真实用量记录；有原证据时保留原证据。无需为本次增加独立失败恢复机制或故障矩阵。

### 2.4 页面、记录与导出同步

复用 `action_steps`、`search_rounds` 和现有结果记录，最少能看出：自主步数上限／已用步数、每步模型动作、实际查询与版本范围、工具观察、是否触顶收尾及最终停止原因。

新查询应有明确的自适应取证标记，不把第二次检索统一叫“补查”，也不把自主选择的动作展示成固定计划执行。页面、历史 JSON 和 Markdown 应展示所有实际轮次；旧记录仍按旧字段正常显示。不要新增独立轨迹数据库、长篇思考展示或另一套日志文件。

本轮不修改旧评测器的指标算法，也不把新循环结果送入仅理解两轮的旧评分器并宣称得到当前效果成绩；该接入留在 2.2。
