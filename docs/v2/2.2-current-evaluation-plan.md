# 2.2：当前流程批量评测与统计适配任务规划

制定日期：2026-10-20（Asia/Shanghai）。状态：实施完成，待原对话审核。2.1 已完成，简单审核未发现阻断问题；本任务只实施 2.2，不实施 QASPER 接入或真实效果实验。

## 1. 目标与边界

让现有开发题能够通过页面当前实际使用的流程，分别运行固定 RAG 与自主 Agent，并正确保存、评分和汇总零次至多次检索的证据与开销。

- 复用 `d9_runtime.run_question(..., library_mode=True)`：固定模式传 `mode="fixed_rag"`，Agent 传 `mode="agent"`，后者沿用 2.1 的五次自主决策及触顶收尾。
- 只适配现有开发集 `eval/dev.jsonl`。原冻结验收集继续留出，QASPER 数据转换及 Answer F1／Evidence F1 留到 2.3。
- 本任务实现准备／执行能力并用模拟响应验证，不执行真实模型、embedding 或重排请求，不下载数据、不重新入库。
- 旧 D8／D9 批评保留原用途；新路径独立选择，不顺带重构旧流程或改写历史结果。
- 不增加哈希、源码快照、manifest、全库扫描、审计、配置保护层、通用评测框架或独立验证报告。

## 2. 已确认的接入问题

旧 `run_paired_case` 在模型决策前共享一次原问题检索，`FrozenFirstSearcher` 只允许原查询／范围回放和一次补查。这与自主 Agent 可以零检索回答、改查询、改论文子集和多次取证冲突，不能只给旧核心调用加上“五步”参数。

旧 `score_agent_case` 将第 2 次检索解释为补查，主要只合并前两次检索。自主路径的 `initial_context` 还是零检索时的初始上下文，不能当作首轮检索后的展示结果。最终上下文也可能包含规则式原文展开或历史恢复的材料，不一定全部来自原始检索候选。

## 3. 必须实现的行为

### 3.1 当前路径的批量入口

优先在 `scripts/run_agent_comparison.py` 增加明确的当前流程选项，例如 `--pipeline current`；默认保留旧调用语义。当前分支直接调用页面 runtime，不经过 `run_paired_case` 或旧共享检索适配器。必要的成对调用／汇总帮助函数可放在现有 `agent_comparison.py`，不复制一套 runtime。

继续默认只准备，只有显式执行选项才允许真实调用；保留已有 `--live`／`--execute-prepared` 的使用习惯。当前分支不进入旧 `freeze_sha256`、源码／来源绑定或旧 manifest 流程。仅记录普通批次输入、题目 ID、完整论文版本配对和可公开的运行配置，不输出密钥。

首版保持顺序执行：每题的两个模式独立调用并关闭资源，不共享首轮检索，不并行打开同一个本地向量库。两边都独立执行真实前置准备，其开销计入各自记录。单边失败保留失败与已发生开销，另一边仍可得到结果。

题目标注、期望要点和期望证据只进入事后评分，不能进入 runtime、检索或模型消息。准备阶段不得构造模型客户端、发向量请求或执行问答。

### 3.2 对照条件与批次结果

同题使用相同原问题、选定版本、生成模型和页面交互策略；检索 top 5、上下文上限及重排设置按实际路径记录。页面策略为 4096 输出 token、单次请求超时及既有重试／修复规则；自主 Agent 另外受五步约束。

这是一组端到端流程对照，Agent 的调用次数可以更多；不能写成相同总 token 或相同检索次数的实验。每份 runtime 返回的实际配置与用量应保留，历史 D10 成绩继续单列。

当前批次使用独立的结果目录，例如 `artifacts/v2/comparison/<batch-id>/`，保存必要的逐题两模式记录、普通状态和汇总。runtime 已保存历史记录，批量层只保存返回值或引用其路径，不对同一运行重复调用保存函数。

复用现有“默认准备、显式执行、已尝试结果不自动重跑”的操作方式即可；已有批次不覆盖，中断或失败保留已有结果，不新增锁、恢复框架或防护文件。新路径若不支持旧 `--resume`，应在执行前明确提示，不隐式回退到旧路径。

### 3.3 全部检索轮次和最终证据的统计

评分优先在 `agent_evaluation.py` 增加当前记录适配；通用状态、引用和代价统计继续复用 `evaluation.py`，只做实际需要的局部修改。

| 项目 | 统计要求 |
|---|---|
| 实际检索 | 遍历全部 `search_rounds`，保留 round、kind、自主步、查询、范围及成功／失败；不按 round=2 推断补查 |
| Returned | 所有实际检索候选的去重并集；失败检索保留为已尝试，合并轨迹中任意条目不能凭空算作已召回 |
| 各轮展示 | 有记录时按 `merge_trace.rounds` 的 `query_index` 对应轮次；不把自主路径的初始空上下文当作首轮展示，也不把合并诊断快照冒充实际模型输入 |
| Final shown | 独立读取最终实际展示原文，结合已有 `reading_origins`、版本元信息和原文／引用来源字段匹配身份；合法的邻近阅读、历史恢复证据可计入展示，不必先被计为 Returned |
| 无检索回答 | 检索次数为 0；可答且有标注证据时，Returned／Shown 按实际材料计分；程序 answered 不能自动计为有据正确 |
| 查询类型 | 自适应取证、计划查询和旧补查按真实 kind 分开；自适应第二次取证不计成旧 retry |

沿用已有指定引文精确匹配规则及来源约束，不扩展为新的语义裁判。评分从保存记录中取证，不重新调用模型、不重读全库 PDF、不生成新的文本哈希或来源审计。

检索尝试数、自主决策步数和真实 API 请求数分别记录。重复动作可能消耗自主步而不发 embedding；触顶收尾、网络重试和格式／引用修复也不能混算成新的检索或自主步。

### 3.4 汇总、分母与费用

至少保留各模式的尝试／完成／失败数量、指定引文的 Returned／Final shown 命中、引用定位、检索次数、自主步数、触顶收尾、停止原因、耗时及实际用量。

用量覆盖前置准备、决策、收尾和修复，保留 embedding、聊天 SDK／HTTP 与重排请求及各自可用的 token／耗时；按各次 runtime 的真实记录相加，不套用旧共享首轮的扣减账本，也不按检索轮数猜测请求次数。

缺失用量仍为 null，同时列已知小计；不改成零。已尝试失败的可答题保留在相应命中指标分母，未尝试题单列。无答案题不进入标注证据命中分母；合理说明依据不足与回答有用性留后续语义评价，不能只按拒答状态判为正确。

机器汇总继续明确：指定引文命中是检索代理，引用定位通过不等于语义支持；`qa_accuracy` 保持未评价状态，不把 answered 比例改称准确率。
