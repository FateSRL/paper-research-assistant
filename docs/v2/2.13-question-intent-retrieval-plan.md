## 3. 任务一：业务问题与输出要求分开传递

### 3.1 使用一个可选输出要求参数

在现有 `run_current_case → d9_runtime.run_question` 路径增加可选 `answer_instructions`，默认空，现有页面与 CLI 调用保持原用法。由运行时把它放入现有 `conversation_context`，通过现有消息构建路径传给回答模型；不新建评测运行入口、问题分类阶段或一套问题状态。

QASPER 的调用调整为：

- `question` 使用官方题目原文，保留原有文字，包括原题拼写；不依据标注润色。
- `answer_instructions` 使用现有英文、同次生成 `direct_answer` 和保留 claims／引用的统一说明。其要求不变，只改变传递位置。
- 问题准备、来源范围识别、检索和重排以业务问题或本轮有效搜索词为输入；输出说明不拼回 query。
- `answer_instructions` 只约束语言和答案表达，不提供论文事实、标准答案、答案类型或证据位置。

无需澄清的首问仍由程序保存原文；多轮仍使用 2.12 已有的指代补全与澄清。只在现有准备提示中整理检索目标约定，不新增准备调用。

### 3.2 记录真实输入

新 QASPER 逐题记录中，`actual_question` 对应实际传入的业务问题，输出说明另存 `answer_instructions`；批次 input 延用既有 `english_instruction` 记录。旧批次、原答案和原评分保留，不迁移或重写历史。

Answer F1 仍读取已发布的 `direct_answer`，证据仍使用全部实际引用。既有 `evaluation_protocol` 和评分规则不变；比较时说明新旧运行的输入组织方式不同。

## 4. 任务二：首轮查询做最小必要改写

在现有 [查询准备](D:/course/paper-research-assistant/paper_assistant/conversation.py:76) 与 [自主决策提示](D:/course/paper-research-assistant/paper_assistant/agent_prompt.py:158) 中整理约定，沿用 [搜索执行](D:/course/paper-research-assistant/paper_assistant/agent.py:410) 路径，不再由程序把首次工具查询替换成原问。

### 4.1 保留信息需求，允许检索表达变化

- 原问题确定所问对象、关系和必要条件；首次查询据此做最小必要的翻译、术语补全或表达压缩。保留原意不要求字符串逐字相同。
- 中文问英文论文时，允许使用论文语言和原文技术名称进行检索。语言选择沿用已有模型与论文材料，不增加语言检测器，也不以“是否含 CJK／题名是否英文”作硬分支。
- 泛问题如“这篇论文主要做了什么”本身允许整体介绍，可以根据所选论文补充题名、研究目标或贡献等检索表达；不能因收紧范围而把它当成不可检索的问题。题名只在帮助定位对象时使用，不统一拼接每篇论文的题名。
- 长问题可压缩为较短查询，保留所问关系、比较对象和限制；必要时用现有多个查询覆盖其子问题，仍受原五步及取证额度约束。原问完整保存，不按固定后缀拆分，也不强行把超长原文送进检索。
- 具体关系题不因为论文另有长语音实验、性能表或机制介绍，就主动扩成这些方向。多轮追问继续依据已经补全必要指代的当前问题规划，历史不扩大本轮任务。

`RETRY_QUERY_MAX_CHARS=1000` 是现有工具查询的字符上限，保持原样；它不是已经确认的 embedding token／输入容量。查询长度继续由现有工具参数处理，不新增长度回退或自动截断路径。

### 4.2 保持当前执行与记录职责

Agent 仍自行决定是否搜索、补读或回答。已有证据足够时可直接回答；不插入额外原问检索，不强制双查询，也不把准备建议变成执行队列。同一响应的多个工具请求继续按现有顺序和额度执行，失败不会自动追加一轮基准查询。

合法工具 `query` 即本次实际搜索文本，继续保留在原始工具请求、`parsed_action` 和 `search_rounds[].query` 中；当前 dense、BM25 和重排已使用同一个 query，保持该行为。不再增加 `proposed_query`、`executed_query` 或 `first_search_mode` 等用于解释程序替换的字段，因为本方案已取消该替换。

首轮改写是否忠实仍属于模型行为，不能由字段传递或 mock 证明。本批通过第 7 节的真实题目检查，保留失败，不预设这次提示整理一定带来召回改善。

## 5. 任务三：后续取证与答案围绕所问关系

### 5.1 整理现有信息缺口约定

当前 [工具调用保存](D:/course/paper-research-assistant/paper_assistant/agent.py:517) 会保留 `SearchAction.missing_information`，[下一轮输入](D:/course/paper-research-assistant/paper_assistant/agent.py:231) 会带入已执行动作，工具调用历史也仍包含该参数。MonaLog 的真实记录已经确认这一点。因此不采用 DS 建议中“当前只写不读、下一轮不可见”的前提，也不为让它首次可见而改造观察协议。

在 [conversation.py](D:/course/paper-research-assistant/paper_assistant/conversation.py:76) 的查询建议说明和 [agent_prompt.py](D:/course/paper-research-assistant/paper_assistant/agent_prompt.py:158) 的自主决策规则中统一以下职责：

- 原问题确定最终需要回答的对象与关系；`planned_queries` 是检索表达建议，不是新的作答提纲。
- `missing_information` 说明还缺哪个所问事实，不能只罗列主题词或把已读模块的流程改成新目标。下一轮结合已经可见的声明与返回原文，判断这一缺口是否解决；有相关片段或出现新 chunk 本身不代表已经答到所问。
- 搜索词可以加入有用的论文名称、原文术语及同义表达，但扩展应服务于所问关系，不能自行增加新的实验条件或比较维度。
- 返回相关段落后，根据当前原文判断所问事实是否取得。若只有使用流程，仍缺来源或选择条件，就围绕这一缺口搜索；若附近章节更有希望，则用现有 `read_context`。
- 如果证据已经覆盖原问，直接回答；没有更多明确取证方向或预算已到时，按既有协议说明具体缺口。

不按疑问词做硬分类，例如不把所有 How 题强制判为“方法题”。不新增答案类型模型、语义相似度阈值、关键词命中规则或独立完成度审核阶段。

评价时从现有工具参数及动作记录读取每次声明的目标，按“是否仍服务原问 → 返回和最终可见原文是否支持它 → 为什么继续取证或结束”对照。只有实现中发现真实字段丢失才修该具体消费者；不把同一声明复制到多层结果当作质量改进。

### 5.2 同一次生成选择直接答案

整理 [context.py](D:/course/paper-research-assistant/paper_assistant/context.py:57) 的共享答案组织约定及 Agent 使用处，替换重复或职责不清的表述，不继续堆叠同义警告：

- 从原问题要求的关系选择对应主张，先把它写入 `direct_answer`；不能仅因其他实验结果更具体，就用结果替代评估方法。
- 当所问关系是评估方法、事实来源或选择条件时，直接答案写出方法、来源或条件本身，并保留理解它所必需的数值、对象和限定。只取得效果或使用流程、尚无法确定所问关系时，按既有约定返回 `Unanswerable`，在 claims 中说明具体缺口。
- 同时明确询问方法与结果时，两部分都应进入直接答案；数值本身构成筛选条件时也应保留。不采用“方法题的结果、得分一律只能放 claims”的排除规则。
- claims 解释直接答案及其必要条件；明确要求的机制、比较和影响仍完整回答。
- 如果完整正文已包含所问事实，直接答案不能只取扩展背景而漏掉核心。保持同一次生成，不在输出后抽取、缩短、重新生成或根据参考答案挑句。
- 保留现有数值、阶段、技术类别和条件约束，以及证据不足时的 `Unanswerable` 约定。

这些是模型决策与生成的行为要求，不是程序已经证明回答正确。最终仍须对照真实题目和原文评价。
