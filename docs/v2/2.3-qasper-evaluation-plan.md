## 1. 目标与交付边界

接入 QASPER 的真实题目、参考答案和证据标注，复用当前页面固定 RAG／五步 Agent 的批量调用，提供本地自动评分。先准备 20 题接入样本，再准备固定 100 题基线样本；真实运行后由脚本汇总，Codex 只需读取汇总与少量失败案例。

本次实施交付数据准备、真实 PDF 入库衔接、显式运行和离线评分工具。允许下载官方 train／dev 原始数据，生成真实样本；默认准备不下载论文、不入库、不调用模型。PDF 获取、embedding 入库和真实问答分别通过明确命令执行，留待工具实施及审核后开展。离线测试使用少量本地样例与模拟调用。

不增加通用评测框架、全量模型裁判、重新人工标注、哈希快照、manifest、审计或额外校验层。不在本任务优化检索、模型提示、Agent 轮数或入库性能，也不同时接入 ScholarQABench。

## 2. 数据来源与样本口径

使用 [AllenAI 官方 QASPER 数据说明](https://huggingface.co/datasets/allenai/qasper)、[官方历史加载器](https://huggingface.co/datasets/allenai/qasper/blob/7bde7e4a9f805bed6c6e79e664c37057263dbc1d/qasper.py)及 [官方评分脚本](https://github.com/allenai/qasper-led-baseline/blob/main/scripts/evaluator.py)。train／dev 原始 JSON 可从官方加载器引用的 [v0.3 压缩包](https://qasper-dataset.s3.us-west-2.amazonaws.com/qasper-train-dev-v0.3.tgz)取得。保留来源、版本和 CC BY 4.0 说明；无需安装 LED、AllenNLP、训练环境或额外数据集框架。

| 样本 | 用途 | 选择方式 |
|---|---|---|
| train 20 题 | 检查数据接入、PDF 对应、证据映射和评分输出 | 从符合条件的官方 train 题目中按固定种子抽样 |
| validation 100 题 | 固定 RAG／Agent 的开发基线 | 在首次运行前从官方 dev／validation 固定抽样，保存题目 ID |
| 官方 test、项目原 20 题冻结验收集 | 后续留出评价 | 本任务不使用、不为调参提前运行 |

先按 `question_id` 排序再用固定种子抽取，记录种子与筛选条件。20／100 均按问题计数，同时列出涉及论文数和实际答案类型分布，不要求凑齐人为配额。官方 dev 在本项目记为 validation，保留原 split 名称，不混入 train。100 题一旦用于调优，就只能称开发基线，不能称独立最终验收。

首版限定文本证据：整题排除任一参考标注含 `FLOAT SELECTED` 的题目，其余题目保留全部参考答案与证据，不挑选容易评分的某一个标注。官方 `--text_evidence_only` 仅删除图表证据项，可能留下空证据，并不等于筛选纯文本问题，因此不能用这个开关冒充同一子集。

保留可答、不可答、抽取式、自由回答和 Yes／No 题。不得根据运行分数、是否容易下载 PDF 或映射结果重新挑题。缺失 PDF、版本不明、映射失败的题保留原 ID 与状态，修复后仍运行原题；尚未运行完时只报告完成部分及缺口。

## 3. 接入现有系统的方式

### 3.1 独立保存 QASPER 标注

建议新增一个薄入口 `scripts/run_qasper_evaluation.py`，将数据转换、段落映射和官方指标适配集中在 `paper_assistant/qasper_evaluation.py`。复用 `agent_comparison.run_current_case` 和 `summarize_current_costs`，不复制页面 runtime，也不把现有批评改造成通用框架。

QASPER 输入放在独立的 `eval/qasper/`，运行结果放在 `artifacts/v2/qasper/<batch-id>/`。保存必要的原始数据、选题、论文对应关系、逐题预测和汇总即可；具体文件可合并，不为每个阶段再生成独立报告。

每题保留原始论文 ID、问题 ID、官方 split、英文原题、所有参考标注，以及带 section／paragraph 顺序的原始 `full_text`。原始证据字符串也保留，用于还原官方评分输入。论文 ID 与本地 `(paper_id, parse_revision)` 的对应关系另存普通数据。

现有 `dev_cases()` 要求人审状态与 PDF 页码／指定引文，不适合直接接收 QASPER。不要追加到 `eval/dev.jsonl`，不要伪造 `human_verified` 或 PDF 页码，也不要用当前 `score_current_case` 的指定引文命中率代替 QASPER 指标。

### 3.2 复用真实 PDF 入库和引用

本项目的存储、引用与页码回查依赖真实 PDF。采用“官方结构化数据用于选题和评分，真实 PDF 用于现有入库与问答”的路线，不新建纯文本问答分支，不把段落编号当作 PDF 页码，不生成模拟 PDF 充当真实语料。

准备阶段输出所需论文 ID、可定位的来源及待提供 PDF 清单。取得真实 PDF 后，显式导入命令接收本地 PDF 与题库论文的对应关系，按论文去重调用既有 `import_runtime.import_pdf`，记录返回的真实版本配对；同一论文不因包含多题而重复入库。已有 ready 版本可在明确对应后复用，沿用项目现有身份和缓存，不另建哈希机制。

QASPER 的论文 ID 不一定注明 arXiv 版本。记录实际取得 PDF 的来源与版本；无法确认时标为待处理，不能静默选择最新版本并声称与官方全文完全一致。这里得到的是基于本地 PDF 的 QASPER 文本子集实验，不宣称复现完整官方排行榜条件。

### 3.3 chunk 与原始段落的映射

对每篇已选论文，先给官方 `full_text` 的全部段落建立稳定 ID，再用已入库的 PDF 文本、segment／chunk 偏移和原始段落做确定性文本对应。映射范围必须覆盖全部段落，不能只在标准答案的证据段落中找对应，否则无关引用会从预测中消失，抬高 Evidence F1。

2.3 首版只做空白、换行与断行连字符归一化；2.6 首轮在同一实现中补充连字、标点、引用及公式表示差异，并对被图文打断的正文做局部有序对齐。保留唯一精确匹配路径，局部匹配要求实际正文锚点与完整普通正文的有序对应，不以相似分数确认。允许一段对应多个 chunk、一个 chunk 跨多个段落；保存真实 PDF 字符范围，图文插入处返回分开的范围。重复文本、正文不足或内容缺失继续保留 unresolved，chunk 还有未对应有效文字时也不整体标为 mapped，不引入模糊匹配平台或模型对齐。

映射读取真实 chunk 及合法阅读来源，保留原始 PDF 页码；评分时回到官方原始段落字符串。映射只供离线评分使用，不把标准答案、标注证据、答案类型或预先找出的正确位置传给检索和模型。

先用 train 20 题观察实际映射覆盖。如果文本差异导致 Evidence F1 无法可靠计算，交付具体缺口与可用的 Answer F1；不为凑齐指标扩展成 PDF 解析重构或全文对齐项目。少量人工复核只确认论文版本和有歧义的对应，无须审核全部论文。

## 4. 执行入口与预测提取

入口提供以下四类明确动作即可，参数名称可按现有脚本习惯确定：

| 动作 | 输入与结果 | 请求行为 |
|---|---|---|
| `prepare`（默认） | 本地官方 JSON → 固定选题、原始标注与所需论文清单 | 不构造模型客户端，不下载 PDF，不调用入库 |
| `import-papers` | 样本、已取得 PDF 与对应关系 → ready 版本及段落映射 | 显式执行现有入库，会发生 embedding 请求 |
| `run` | 样本、明确的 ready 配对、批次 ID → 两模式独立运行记录 | 显式执行真实模型／检索／重排请求 |
| `score` | 已保存预测、标注与映射 → 逐题分数及汇总 | 纯本地，不重新运行问答或请求模型 |

下载官方 JSON 是一次数据准备操作，不必专门开发下载调度器。缺少输入时明确指出所需文件；无参数运行不能隐式导入论文或开始问答。真实运行先做 train 20 题，查看映射与开销后再显式运行已选 validation 100 题。

每题只把问题和对应的真实论文版本配对传入 `run_current_case`，两模式均走 `library_mode=True` 的当前页面流程，独立前置准备，Agent 继续五次自主决策及触顶收尾。保持 2.2 的配置、全部轮次与实际用量口径。runtime 已保存历史，不重复保存同一运行；旧批次不覆盖，失败与未尝试状态保留，不另做恢复框架。

使用英文原题；如当前提示仍造成中文回答，可统一追加固定的英文作答要求，两个模式一致，分别保存原题与实际输入。不得依据标准答案改写问题或补充提示，不为提高词重叠把正式回答流程改成另一套抽取器。

从最终实际发布的 `answer.claims` 按顺序提取正文作为预测答案，不混入引用编号、JSON、执行轨迹或中间失败草稿。不根据参考答案挑句子、截短或重写，也不另调模型翻译／裁判。仅当真实输出明确为 `insufficient_evidence` 等现有拒答状态时，转为官方 `Unanswerable`；无检索、引用少或参考答案不可答，都不能代替真实拒答状态。

Evidence F1 的预测取最终实际引用的证据，经 chunk／阅读来源映射为原始段落并去重。所有召回结果和最终展示上下文只作分开的检索诊断，不能全部冒充最终回答选择的支持证据。

## 5. 自动评分与汇总

### 5.1 沿用官方指标

复用官方 evaluator 的小型评分函数或等价实现，保留来源说明；无需引入官方模型和训练依赖。

- **参考答案转换：** 每条标注按官方优先级处理：不可答 → `Unanswerable`；非空 `extractive_spans` → 用 `, ` 连接；其次 `free_form_answer`；其次 `yes_no=True` → `Yes`，`False` → `No`。不能把 False 当成缺失。
- **Answer F1：** 使用官方的小写、ASCII 标点、英文冠词及空白归一化与词级 F1；对全部参考答案取最大值，再按问题平均。不得把它称为人工准确率或语义正确率。
- **Evidence F1：** 将预测还原为官方原始段落字符串，按官方集合交集及数量计算；对各参考证据分别评分后取最大值。Answer／Evidence 可以分别命中不同参考标注，不能只用 Answer F1 最优的那条证据。预测证据去重；双方证据都为空时为 1。
- **缺失预测：** 已尝试但失败、未发布有效答案的题保留在已尝试分母，按官方缺失预测记两个指标为 0，另列失败原因；未尝试题单列。未全部尝试时，不把当前均分写成完整 100 题成绩。

### 5.2 映射不完整时不制造精确分数

逐题保留 `evidence_mapping_status`。存在未映射／歧义的最终引用，或该题任一参考证据无法可靠对应当前 PDF 时，该题 Evidence F1 为 null，列出涉及的段落／chunk ID；不能丢弃这些引用后计分，也不能把 gold 改为空或只保留能映射的参考答案。Answer F1 仍按真实预测独立计算。

对已尝试失败且没有发布预测的题，保留官方缺失预测的 0 分，不用映射缺口隐去失败。对成功发布答案的题，原始官方空证据按真实标注计分，不把解析失败混成空证据。

汇总列出固定样本数、涉及论文数、ready／待处理论文数、未尝试／已尝试／成功／失败题数，以及映射可评分题数和覆盖率。全样本可算时给出 Evidence F1；存在 null 时全样本 Evidence F1 标为未完整可评，只另列有明确分母的可映射部分分数。两模式比较 Evidence F1 时使用共同可评的题目集合，并说明其占固定样本的比例。

按模式保留 Answer F1、Evidence F1 的适用范围、真实耗时、模型／embedding／重排请求和已知 token 小计、缺失用量、自主步数、触顶与停止原因。用量直接复用 2.2 账本，未知仍为 null，不因接入数据集重写费用统计。公开标注不提供 PDF 页码真值，引用可定位与答案语义支持继续分开解释。

Codex 默认只读取汇总与最多 5–10 个代表性失败／映射争议案例，不加载全部全文或逐题人工批改。主要看失败发生在哪一层及两模式差异，不预设某个 F1 阈值就能证明系统成熟。

## 6. 实施步骤与必要验证

| 步骤 | 交付 |
|---|---|
| A | 读取官方 JSON，下载并准备真实 train 20／validation 100 固定样本，保留全部参考标注及筛选计数 |
| B | 提供真实 PDF 的显式导入衔接、现有 ready 版本对应与确定性段落映射；此阶段不实际调用 embedding |
| C | 复用当前两模式运行函数，提取最终预测和实际引用，提供官方评分及覆盖率、失败与用量汇总 |
| D | 完成下列少量离线验证，更新本文件与总计划的实施状态；真实入库／问答状态另列 |

现有 2.2 已通过且未变化的验证直接复用。QASPER 是新增格式，建议增加 `scripts/check_qasper.py`，只点选两个有实际覆盖价值的方法：
