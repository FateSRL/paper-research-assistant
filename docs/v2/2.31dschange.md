# 2.31dschange：对 2.13 的修正建议

制定日期：2026-10-24（Asia/Shanghai）。状态：建议稿，尚未实施。本文只修改规划，不修改业务代码、不运行测试、不发真实模型／embedding／重排请求。对象是 [2.13：原问题约束检索目标与直接答案](2.13-question-intent-retrieval-plan.md)。

依据：2.13 原文、当前代码（`agent.py`、`agent_actions.py`、`agent_prompt.py`、`conversation.py`）、本地 RAGFlow 实现（`E:/project/ragflow`）。

## 1. 结论

2.13 的以下部分保留，不做改动：

- 任务一：业务问题与输出要求分开传递（§3）。
- 5.1：复用现有 `missing_information`，不新增同义 intent 字段，不按疑问词硬分类（§5.1）。
- 7.2：三题按“检索偏移／证据取得／直接答案选准”分阶段记录（§7.2）。
- 不新增校验器、审核模型、哈希或审计报告。

建议修正的四处：

| 编号 | 2.13 现状 | 建议 |
|---|---|---|
| 修正一 | §4 第 2 条：首次实际搜索无条件使用业务原问 | 改为带守卫的基准查询，避免跨语言、泛问题和超长问题退化 |
| 修正二 | `missing_information` 必填但只记录，不进入观察与结果字段 | 让模型下一轮看到自己声明要找什么，评估也能逐轮对照 |
| 修正三 | §5.2 的直接答案规则偏抽象 | 增加一条针对“方法／来源／条件”类问题的可执行规则 |
| 修正四 | 验证只有三道英文 QASPER 题 | 补两个页面路径回归场景；归因建议两阶段运行 |

## 2. 修正一：首次检索从“替换”改为“受约束的基准”

### 2.1 问题

2.13 §4 第 2 条要求在 Agent 首次实际请求 `search` 时，程序把该次真实搜索文本替换为业务原问。现有代码位置是 [agent.py:410](../../paper_assistant/agent.py) 的 `execute_search`。

无条件替换至少有三个反例：

1. **中文问题问英文论文。** 页面是中文入口，用户很可能中文提问。原问直接进检索，BM25 词法一路基本失效；跨语言向量也许能撑住，但首检只有一次。现有提示本来就要求模型用论文语言生成查询（[agent_prompt.py:104](../../paper_assistant/agent_prompt.py)），替换等于放弃这条约束。
2. **泛问题几乎没有检索信号。** “这篇论文讲了什么”“What does this paper do?” 这类首问，模型本来会补标题和综述词；替换后召回质量会下降。2.13 只排除了“为通用问题自动插入搜索”，没有排除“模型请求搜索时覆盖它的查询”。
3. **超长问题。** 2.13 明确不截断原问；但 embedding 输入有长度边界，长问题会退化或失败。现有查询上限是 1000 字符（[agent_actions.py:18](../../paper_assistant/agent_actions.py)）。

2.13 的三道 QASPER 题都是英文、且都是具体关系题，恰好避开了这三个场景，因此测不出回归。

另外，RAGFlow 没有“用原问检索”的做法：它的 `queries` 由模型生成，`intent` 只描述本次需要什么事实；`navigate_tree` 使用原问措辞，但那是结构路由，不是 BM25／向量检索。2.13 §2 已承认“不是声称 RAGFlow 强制首检使用原问”，本文沿用这一界定。

### 2.2 建议规则

首次实际 `search` 的实际执行查询按以下顺序确定，全部由程序执行，不增加模型调用：

1. **基准构造**：`baseline = 业务问题 + " " + 本次 search 所涉版本的题名`。题名来自已存元数据（`paper_information`），按 `action.selected_versions` 选取、去重；题名不可用时只使用业务问题。题名给泛问题提供检索信号。
2. **语言守卫**：业务问题含 CJK 字符，且本次所涉所有版本的题名均不含 CJK → 不执行 baseline，保留模型 `query`，记录 `first_search_mode="language_guard"`。依据是模型查询已被现有提示要求使用论文语言。
3. **长度守卫**：`baseline` 超过 1000 字符（与 `RETRY_QUERY_MAX_CHARS` 一致）→ 保留模型 `query`，记录 `first_search_mode="length_guard"`。不截断、不按后缀拆分原问。
4. **其余情况**：执行 `baseline`，记录 `first_search_mode="baseline"`。模型查询未执行时，也保留为 `proposed_query`。
5. **首检判定**：以本轮是否已尝试过实际检索为准，而不是以是否成功为准；首次尝试失败后不补一轮“成功基准”，与 2.13 §4 第 5 条一致。
6. **一致输入**：检索与重排使用同一个 `executed_query`（`hybrid_search.search_evidence` 的重排也接收该 query），这一点 2.13 未写明，需要明确。
7. **记录**：`search_rounds[]` 使用实际执行文本；observation 同时给出 `executed_query`、`proposed_query` 和 `first_search_mode`（仅首轮有值），下一轮模型能知道实际搜过什么。

### 2.3 不改变的部分

- 不增加检索轮次、不改检索参数、重排模型、上下文预算和五步额度。
- 只改首次实际检索；后续检索继续使用模型查询。
- 非自主 Agent 分支与固定 RAG 不在本批。

## 3. 修正二：让缺失信息声明真正可见

### 3.1 现状

`SearchAction` 已强制要求 `missing_information`（[agent_actions.py:94](../../paper_assistant/agent_actions.py)），形式上是 RAGFlow 的 intent。但：

- `execute_search` 构造 observation 时没有包含它（[agent.py:414](../../paper_assistant/agent.py) 附近）；
- `search_rounds[]` 只记录检索本身的 query 与结果，没有“本次声明要找什么”；
- 结果是模型下一轮只看到返回结果，评估也看不到目标与结果的对照。

它目前只是一个被记录下来的句子，不参与观察、停止和判断。

### 3.2 建议

1. observation 增加 `missing_information` 和 `executed_query`（首轮另有 `first_search_mode`）。这是把模型自己声明的目标原样回显，不是新增判断。
2. `search_rounds[]` 每轮记录 `missing_information`、`proposed_query`、`executed_query`；首轮另记 `first_search_mode`。
3. 不接入 RAGFlow 的 decision model，不自动丢弃“不服务目标”的段落。2.13 已明确不接额外审核模型；本文不改变这一范围。
4. 预期要写清楚：这是可观测性改进，不保证模型因此改变行为。行为效果仍靠 5.1 的提示规则和人工评价；不能把“字段有了”当成“问题解决了”。

## 4. 修正三：§5.2 直接答案规则具体化

在 2.13 §5.2 现有条目后增加一条，不新增字段、不改输出结构：

> 当原问题问的是“如何评估／如何选择／从哪里获得／按什么条件”时，`direct_answer` 必须写出方法、来源或条件本身；实验结果、得分或机制表现只能放进 claims。若可见证据只有结果、没有所问关系，`direct_answer` 使用 `Unanswerable`，并在 claims 中用 gap claim 说明缺什么。

说明：

- 不按疑问词硬分类，仍由模型判断问题对象；规则只覆盖 2.13 已定位的两类失败（评估方法、事实来源）。
- 保留“同一次生成、不做输出后抽取、缩短或按参考答案重写”。
- 这是提示词级要求，不保证语义正确；仍按 7.2 人工对照原文。

## 5. 修正四：验证与归因

### 5.1 离线方法

复用 2.13 §7.1 的三个现有方法，不新增方法。在 `check_d9_e_runtime.test_original_query_and_complete_pairs_preserved` 中扩展示例：

| 示例 | 预期 |
|---|---|
| 英文具体问题 + 英文论文 | 首检为“原问 + 题名”，`first_search_mode=baseline` |
| 中文问题 + 英文论文 | 首检保留模型 query，`first_search_mode=language_guard` |
| 泛问题 + 有题名 | 首检包含题名，`first_search_mode=baseline` |
| 超长问题 | 首检保留模型 query，`first_search_mode=length_guard` |
| 首次检索失败 | 仍算已尝试，后续不补“成功基准” |
| 任意一轮 | observation 含 `missing_information` 与 `executed_query` |

全部使用 mock／本地材料，不发真实请求。

### 5.2 真实运行

1. 保留 2.13 的三道 QASPER 题，各一次 Agent（英文，baseline 分支）。
2. 增加两个页面路径回归，需单独授权，不进入 QASPER 批次、不参与评分：
   - 中文问题问一篇已 ready 的英文论文（复用现有 Raft 或本批自然度论文）；
   - 泛问题“这篇论文主要讲了什么”问同一篇论文。
   只记录首检模式、关键证据是否召回、直接答案是否覆盖所问关系；不作为准确率或 benchmark。

### 5.3 归因

建议分两阶段，而不是把所有改动一次跑完：

- **阶段 A**：只做任务一（输入分离）+ 修正二的观测字段，跑三道 QASPER。得到“管线与观测就绪”的基线。
- **阶段 B**：加修正一、三、5.1 的行为规则，再跑三道 QASPER。对照阶段 A 看首检模式、关键证据是否召回、直接答案是否对准。

若用户不接受 6 次 Agent，则只跑阶段 B 一次，并在结论中明确“整套改动，不单独归因”（与 2.13 §7.2 末尾一致）。两阶段是建议，不是必须。

### 5.4 每题记录字段

沿用现有批次结构，增加以下可读字段，不新建报告：

| 字段 | 含义 |
|---|---|
| `first_search_mode` | baseline／language_guard／length_guard／model_query |
| `executed_query` / `proposed_query` | 实际执行文本／模型原始请求 |
| `missing_information` | 每次 search 声明的信息需求 |
| `gold_chunk_retrieved` | 关键原文是否进入本次返回（自然度 `p4_c2`、MonaLog `p3_c1`） |
| `gold_chunk_in_final_context` | 是否进入最终可见证据 |
| `direct_answer_covers_asked_relation` | 直接答案是否写出所问关系 |
| `claims_supported_by_cited_text` | 逐条引用是否支持对应结论（人工） |

参考答案、WordNet／MOS 等诊断要点和已定位正确块不进入准备消息、搜索词或工具输入。

| 1 | `scripts/run_qasper_evaluation.py`、`agent_comparison.py` | 官方问题与输出说明分开调用、记录，透传可选 `answer_instructions`（同 2.13 任务一） |

## 7. 不做什么

- 不新增与 `missing_information` 同义的 intent 字段。
- 不接入 decision model、独立审核阶段或自动丢弃段落的过滤。
- 不做疑问词硬分类，不新增题型模型。
- 不新增校验器、哈希、审计、快照、保护层或验证报告。
- 不重新解析、分块、入库、重建向量或重算映射。
- 不修改评分公式，不补跑低分题，不在结果出来后调参重试。
- 不把三题说成留出评测或总体准确率。

## 8. 完成与停止

代码完成的标准：

- 业务问题与输出说明分开传递；
- 首次实际检索按规则记录 `first_search_mode`、`executed_query`、`proposed_query`；
- observation 与 `search_rounds[]` 含 `missing_information`；
- 2.13 §7.1 的三个既有离线方法通过。

语义完成的标准：

- 三道 QASPER 题（以及授权的两个页面回归）按 §5.4 记录；
- 仍偏题或仍未取到关键事实时，保留原始结果，说明发生在哪一环，不自动重跑、不追加题目、不继续调提示。

完成上述运行后结束本批。

## 9. 与 2.13 的逐条差异

| 2.13 条款 | 本建议 | 原因 |
|---|---|---|
| §4 第 2 条无条件使用业务原问 | 加题名与语言／长度守卫，按模式记录 | 跨语言、泛问题、超长问题会退化；三题英文测不到 |
| §4 未说明重排输入 | 检索与重排使用同一个 `executed_query` | 避免记录与实际不一致 |
| §4 第 5 条只保留原始请求 | 同时记录 proposed／executed 与 mode | 归因需要知道实际执行了什么 |
| §5.1 复用 `missing_information` | 让声明进入 observation 与每轮记录 | 当前字段只写不读，作用有限 |
| §5.2 行为要求 | 增加“方法／来源／条件”类问题的具体规则 | 两题失败都属这类，抽象要求不够 |
| §7.2 三题一次运行 | 建议两阶段；否则声明不归因 | 四处改动同时发生，单次结果无法归因 |
| §7 只跑 QASPER | 增加两个页面路径回归（需授权） | 页面路径才是中文产品入口，QASPER 测不到语言回归 |
