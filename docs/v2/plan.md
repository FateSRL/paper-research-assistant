## 2. 目前需要改善的问题

### 2.1 Agent 在执行过程中的决策权不足

任务规划见 [2.1：模型自主取证闭环](2.1-agent-loop-plan.md)，已由另一个对话实施，本对话简单审核未发现阻断问题。首版交付页面 Agent 的检索／回答闭环，复用四个已通过的相关离线测试方法，本次未重复运行；效果收益待评测。

**改造前的问题：** 前置理解和子查询规划由模型完成；简单路径有一次受限补查。复杂路径则由程序执行全部计划查询，再进入仅允许回答的最终阶段，模型不能根据实际证据调整后续行动。2.1 已补齐检索／回答闭环；原文邻近片段仍由规则展开，模型主动读取工具留待必要时另行安排。

**建议方向：** 参考 PaperQA2，把现有 RAG 包装成取证工具，统一为“模型选择动作 → 程序执行 → 返回观察 → 模型再次决策”。先复用现有检索和回答能力，允许模型指定查询与论文范围、继续取证或提前回答；需要定向阅读时，再将原文读取能力开放为工具。前置计划作为初始建议，执行中允许调整。主要涉及 [动作接口](../../paper_assistant/agent_actions.py)和 [Agent 编排](../../paper_assistant/agent.py)，不需要重建检索系统。

**轮数口径：** 建议首版最多 5 次自主动作决策，允许提前结束；触顶后仍未完成，再做一次仅基于已有证据、说明缺口的收尾。这里采用“5 次自主决策＋触顶收尾”的定义，不等于最多 5 次模型请求。独立前置理解、工具内部模型调用、网络重试和格式修复分别统计。5 是初始工程参数，尚无实测证明最优；后续看平均步数、触顶比例和额外步骤的质量收益。

**建议方向：** 根据失败发生的位置决定改动，先观察以下几层：

| 失败现象 | 优先检查 |
|---|---|
| 必要证据未进入候选集 | 查询表达、分块、混合召回 |
| 候选集中有证据，重排后丢失 | 重排与候选截取 |
| 各查询找到材料，最终上下文缺少一部分 | 去重、合并与上下文分配 |

| 追问理解错对象 | 历史整理、指代消解与澄清 |
