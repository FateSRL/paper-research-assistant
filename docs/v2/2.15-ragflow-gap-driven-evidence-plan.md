## 3. 新数据流：定位候选，按缺口阅读，再准备事实

### 3.1 仅接入自主页面 Agent

范围继续为 `mode="agent", library_mode=True`。保留 2.14 已接通的事实准备和独立最终生成，论文结论仍不能经旧直答旁路发布。固定 RAG、旧非自主 Agent、普通 CLI 和纯通用知识／聊天入口沿用原有行为。

```text
原问题 + 当前可见原文 + 工具返回的候选定位
        ↓ 现有自主决策
search 定位 / read_context 定向阅读
        ↓ 当前阅读目标优先进入证据窗口
prepare_answer：原子事实 + 原句 + 来源 + 所问缺口
        ├─ 核心可答 → 独立最终生成 → 现有发布
        ├─ 核心不足且有额度 → 下一步补证决策
        │      ├─ search / read_context → 新原文 → 再准备
        │      └─ 显式无可靠方向 → 依据已有事实与缺口最终生成
        └─ 已达上限 → 依据已有事实与缺口最终生成
```

模型仍自行选择与原问有关的阅读目标和查询。程序负责真实执行、上下文展示、动作分流和原额度，不根据事后诊断替模型选定正确章节。

### 3.2 已返回但未展示的候选保持可读

复用现有 `search_rounds`、`tool_observation`、`context_reads` 和阅读目录：

- 搜索的 `returned_ids` 与实际 `shown_ids` 继续分别记录，不把检索返回当作模型已读。
- 在现有工具观察中，为未展示的真实返回块提供精简定位信息：`chunk_id`、所属论文／版本、页码／章节、已有 `parent_id` 和省略原因。信息取自本轮实际 `search.results` 及选择结果，不生成另一份模型摘要。
- 定位信息用于选择阅读目标，不赋予原文引用权限。实际原文展示后才进入当前 `allowed_citation_ids`。
- 复用现有 token 计量和消息视图预算，将新增定位信息纳入展示成本；不把未展示全文藏入工具历史绕过预算，也不重复展示同一段全文。

已经显示且足以回答的问题直接准备事实；不为了对齐 RAGFlow 的工具描述强制重读已有完整原文。

### 3.3 复用 read_context 增加定向块读取

保留已有 `{parent_id}` 调用，并增加定向形式 `{chunk_id, missing_information}`：

- `parent_id` 与 `chunk_id` 二选一；旧父块调用保持可用。`missing_information` 在新增定向形式中说明本次缺少的事实，旧调用可以省略。
- `chunk_id` 来自本轮真实工具返回或实际已展示的块；复用现有论文版本和来源资格检查，只读已保存原文。父块入口继续使用已有可访问阅读目录。
- 单块入口默认只读目标块，不自动把整个父块及邻居一并塞入。需要上下文时仍可使用已有父块阅读能力。
- 每次原生 `read_context` 仍占现有一次取证额度；本地读取不产生新的 embedding、重排或模型过滤请求。

本次实际读取的目标块优先进入当前证据窗口，然后保留当前问题已准备事实所依赖的可用原文，剩余空间再填旧背景和自动邻接内容。历史主动读取的块不永久占据最新目标之前的位置。通过调整候选优先级与减少背景腾出空间，继续使用当前 8,192 token 证据选择上限。

复用现有 `returned_ids/shown_ids/not_shown_ids/visible_chunks` 记录实际阅读结果。目标仍无法展示时保留真实原因，不能报告已读成功或据此宣称缺口解决；不重新分块、不裁剪成伪造原句，也不绕过既有预算。

### 3.4 原文、事实和最终表达保持实际数据依赖

补证后的准备使用当前问题、新展示的目标原文及仍需的已读原文；已有准备事实只作为本轮整理材料，不能脱离对应原句升级为已核实结论。窗口取舍同时保留仍用于回答的主体、限定和必要上下文，不让背景占用挤掉新目标，也不静默丢弃已取得的核心条件。

沿用现有引用与来源视图：原文未展示、或从当前可用证据中移出的块，不能仅凭旧定位信息继续获准引用。下一次准备所需的已读原文可重新进入当前窗口；不另建永久事实缓存或从历史完整答案恢复事实。

独立最终生成继续消费最近一次准备的事实、原始引句、来源限定、原问题及具体缺口，不重新放入整批搜索正文或无关历史。局部符号不清只影响该局部关系；可读的来源与条件正常回答，保留 2.14 的原子、忠实和不加强结论约定。

## 4. 准备不足后的继续与停止必须明确分流

### 4.1 保留准备协议，收紧下一步合同

继续使用 `prepare_answer.facts / answerable / missing_information`，不增加嵌套检索计划或同义缺口字段。

准备返回 `answerable=false` 且还有决策步、取证额度时，程序保存该准备动作，下一次现有自主决策进入内部补证状态。该状态提供：

- 原生 `search/read_context`，针对当前缺口实际补证。
- 现有 [InsufficientEvidenceAction](D:/course/paper-research-assistant/paper_assistant/agent_actions.py:116)，以 `action="insufficient_evidence"` 和 `reason` 明确表示没有可靠的继续取证方向。

此时不接受对同一批未改变原文再次返回准备不足来代替决定。收到重复准备时走已有动作修复预算，要求返回当前允许的取证动作或显式无方向动作，不把它隐式转换成停止。

`insufficient_evidence` 仅在已有待补证事实包的上述状态开放。它不直接发布论文回答，而是让程序用保存的事实包、原缺口及停止理由进入原有独立最终生成；不把该动作重新解释成新的产品终态，也不重新开放论文直答旁路。

### 4.2 无方向要有具体理由，不能用动作重复推断

删除“前一个动作也是 `prepare_answer` 就认定 `no_direction`”的判断，并移除提示中对应的连续准备收尾约定。

无可靠方向的 `reason` 应说明为什么当前工具入口、已读候选或可用线索无法有效补缺，例如来源范围下无可读入口、候选已阅读仍无所需事实且没有新的可靠线索。仅复述“当前缺少所问事实”不能作为同义的无方向说明。

模型仍承担是否有可靠方向的判断；非空理由或结构解析通过不代表程序已经完成语义审核。本批通过显式动作表达并消费继续／停止决定，不新增用于证明停止理由正确的模型或校验器。

### 4.3 工具结果决定后续状态，额度继续共用

- 成功展示新的原文后，退出补证状态，允许再次准备；`missing_information` 是否解决由模型结合原文判断，不能用新块数量替代。
- 重复查询、阅读失败或 `no_new_shown_evidence` 保留实际观察。仍有额度时可根据该结果换有依据的方向，或显式说明无可靠方向；不能把工具失败当成补证成功，也不无条件要求耗尽额度。
- 每次准备和补证决策均计入原五步；search 与 read_context 共用原五次取证。补证不是额外不计步的循环。
- 已到步骤或取证上限时，按现有上限收尾路径整理可用事实与具体缺口，再执行最终生成。第五步不再发新的探索工具，第六步探索不开放。
- 最终阶段无工具，每个逻辑问答只执行一次正常最终生成；格式／引用修复继续共用原修复额度。
