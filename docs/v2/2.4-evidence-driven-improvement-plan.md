## 1. 目标与边界

用当前版本的真实失败案例确定优先问题，完成必要的局部改动，并用同题结果观察是否解决问题。每次围绕一个已确认原因改进，优先解决“材料找不到、找到却未展示、展示却未正确使用”中的实际瓶颈。

先分析已有结果，再决定是否改代码。没有真实基线时，2.4 保持待实施，不通过增加诊断平台、通用评分器或提前重写模块来代替效果实验。2.3 的 PDF 获取、显式入库与基线执行继续按其原规划开展，不在本任务另造入口。

沿用当前向量＋BM25、RRF、重排、上下文合并与回答能力。top 5、最多 8 条完整片段／8000 字符及五次自主决策是当前对照条件，尚不能当作已证明最优的配置，也不因开始 2.4 就统一增大。

保留模型自主决定检索或回答、允许提前结束的方式。首轮不扩 Agent 轮数、不新增固定自检步骤或多 Agent，不优化入库性能，不增加全量模型裁判、哈希、manifest、审计或额外校验层。

先区分未尝试、运行失败、PDF／版本对应问题、证据映射不可评分和真正的回答质量问题。前几类按既有口径保留状态与分母；其中数据对应问题回到 2.3 处理，不能当作检索算法落后，也不能删除这些题让分数变高。

### 2.2 脚本筛记录，Codex 只读少量相关片段

先读取汇总和逐题分数，在本地筛选最多 5–10 个代表性案例，包括低分成功回答、两模式差异明显、运行失败或触顶且开销较大的题。只读取所选题的原问题、全部参考答案、相关证据、最终回答及必要执行轨迹，不加载全部论文。

QASPER 的 `summary.representative_issues` 目前主要包含运行失败与映射缺口，不包含所有低分成功回答，不能只看这个列表。可直接从逐题 `scores` 筛选，无须先为筛题开发新工具。抽查所得原因只描述已看案例，不外推为整个数据集的错误比例。

低 Answer F1 是筛选线索，不直接等于语义错误。先判断是否为同义表达、回答较长或语言不一致，再确认有无事实错误、遗漏问题要点或无依据补充。不能为了词重叠而按 gold 裁剪答案、修改评分规则或把产品改成只输出参考答案片段。

## 3. 按现有记录定位失败

当前混合检索在 `hybrid_search.HybridEvidenceSearcher.search_evidence`：dense／BM25 各取 20 个候选，经 RRF 融合，再按实际设置重排，最终返回 top 5。已有 `retrieval_trace` 保存各路召回、融合与重排记录；`merge_trace` 保存去重、数量／字符截断和最终展示信息，先复用这些记录。

2.2 的 `returned` 指各轮实际返回的 top 5，并非原始召回池。判断证据在哪一层丢失，应结合对应轮次的 trace、真实论文版本及所需的 SQLite 原文，不能看到 returned 未命中就直接归咎于 embedding。

| 观察到的现象 | 需要确认的现有材料 | 条件性处理位置 |
|---|---|---|
| 原始资料有答案，已入库文本缺失 | 所选版本、相关 PDF 原文及对应 segment／chunk | 先区分版本、解析与分块；有证据才局部修复，需重新入库时单列实际请求 |
| 已入库有必要材料，两路召回池均没有 | 实际查询、范围、dense／BM25 记录与相关原文 | `hybrid_search.py`、`lexical_retrieval.py` 或查询表达 |
| 召回池有材料，融合／重排后未进入 top 5 | 同一轮的候选 ID 与各阶段排名、重排是否成功或回退 | RRF／重排与截取规则，不先改分块 |
| top 5 或后续阅读有材料，最终未展示 | 全部 `search_rounds`、`merge_trace`、最终 `context.shown_evidence` 及截断原因 | `agent_context.merge_planned_context`、`context.select_context` |
| 最终已展示必要材料，回答仍遗漏、曲解或夸大 | 原问题、最终主张、所引原文及实际模型输入 | `agent_prompt.py`、`context.py` 的回答组织与提示；必要时局部调整 `generation.py` |
| 引用可定位，但不支持对应主张 | `claims[].basis/citation_ids`、引用原文与主张的关系 | 回答及引用使用规则，不能以定位通过率代替语义支持 |
| 反复取证或触顶仍没解决问题 | `action_steps`、查询及版本范围、工具观察、新增展示、最终引用和停止原因 | 先改善查询／行动提示或已确认的观察传递问题 |

对多参考答案，不只检查词重叠最高的一条；存在其他有效证据或合理回答时保留这种可能。不能仅因没有使用某一指定段落就认定回答错误。

已有记录通常足够完成上述局部分析。仅当选定案例确实缺少一个影响归因的字段时，在其所属现有记录中补最少信息；旧记录无法证明的阶段标为未知，不推测，也不补造全链路日志或来源审计。

## 4. 选定问题后的改动范围

### 4.1 本轮已选定：取证衔接与定向结构修复

直接复用已确认的四个真实失败，不重新开展一轮全面审核：

| 案例 | 实际行为与失败原因 | 本轮对应改动 |
|---|---|---|
| Agent D2-003 | 未搜索；读取规划用摘要后直接输出 `paper_evidence`，但 `citation_ids=[]` | 需要论文事实而当前没有可引用证据时，引导模型选择检索，再基于允许引用的材料回答 |
| Agent D5-006 | 未搜索；题目询问项目发布日期，超出所选论文范围，仍输出无引用的 `paper_evidence` | 明确资料范围与回答依据；不把无依据的结论标为论文证据，也不为了通过格式而强行找引用 |
| Agent D3-002 | 检索成功且已有 5 条证据；将 `reason` 放在动作顶层，而非 `answer.reason` | 明确 Agent 答案层级，并在修复消息中指出具体的多余字段位置 |
| 固定 RAG D6-004 | 已有 5 条证据及所用引用；草稿缺少必填 `status` | 明确固定 RAG 草稿的必填字段，修复消息直接指出 `status` 缺失 |

**改动一：取证、依据分类与输出约定保持一致。** 优先就地调整 `agent_prompt.py` 的自主动作提示，以及 `context.py` 中实际用于固定回答的输出约定；已有示例能说明的内容直接补清楚，不叠加多套提示。

- `selected_papers` 中的标题／摘要仍只供规划，不能因为模型看过这些文字就当作本轮可引用证据。对需要核实的论文事实，若当前没有支持材料且阶段允许检索，引导模型自主选择 `search`；获取材料后只能使用当前 `allowed_citation_ids`。
- 保留直接回答能力，不强制所有问题先检索。对于项目发布日期等所选论文无法确定的问题，可在现有 `answer.status="answered"` 结构中说明范围限制、提供明确标为 `analysis` 的查找建议；不能声称“项目尚未定发布日期”，也不能凭未搜索就断言全文不存在某项事实。
- `paper_evidence` 继续要求非空且合法的引用。一般知识与分析按真实依据分类，不能只把论文事实改标为 `model_knowledge` 来绕过引用要求，不能编造引用、自动补 ID 或将规划摘要直接升级为证据。
- 就地明确两种完整的最小输出示例：Agent 动作为 `action` 加嵌套 `answer`，`status`／可选 `reason` 属于 `answer`；固定 RAG 直接输出含必填 `status` 的 `AnswerDraft`。继续沿用现有 schema，不放宽字段、层级或依据约束。

**改动二：将具体字段问题传给现有一次修复。** 当前解析将校验异常压成通用错误码，修复模型看不到“缺少 status／顶层 reason 多余／论文证据缺引用”等具体原因；原始记录显示它会重复相同错误。这支持改进反馈，但不能预写改后一定成功。

- 在 `agent_actions.py`、`generation.py` 的现有解析失败处，提取足够定位本次问题的字段路径和错误类别，形成简短修复提示；保留既有 `invalid_action_schema`／`invalid_draft_schema` 主错误码和拒绝行为，不另建通用错误框架。
- 优先覆盖已发生的三类问题：缺少必填 `status`、Agent 动作顶层多余 `reason`、`paper_evidence` 对应的 `citation_ids` 为空。路径需区分 Agent 的 `answer.status`／`answer.claims[0].citation_ids` 与固定草稿的 `status`／`claims[0].citation_ids`；规则面向字段，不能硬编码题目 ID 或参考答案。
- 沿既有错误对象、`agent.py` 的动作请求和 `agent_prompt.py` 的 `build_action_repair_messages` 传递反馈；固定 RAG 在 `generate_draft` 的修复消息中传递。复用实际请求记录，不新建日志文件。解析不到具体字段时沿用已有通用反馈即可。
- 保留现有错误摘要不复制原始输入的约定：只输出字段路径、必要类别及固定短提示，不直接回传完整 Pydantic 异常、`input`／上下文或任意异常字符串。原响应仍按既有方式作为 assistant 消息参与修复，不为此新增脱敏平台或额外保护层。
- 对空引用的论文主张，反馈既要指出缺失，也要提醒不得编造 ID；只有当前阶段允许 `search` 且尚有自主步数时才能转为取证。触顶收尾、仅允许终态的引用修复阶段仍遵守原动作限制。
- 修复继续沿用原问题、当前证据、论文范围与共享预算，最多一次；格式修复不额外计自主步，不增加重试次数、模型自检或裁判。不自动补 `status`、搬移字段、删除主张或改写依据来掩盖原输出错误，修复仍失败则保留失败记录。

实施时先处理取证／输出约定，再接通定向反馈，分别说明所改行为。`schemas.py` 与引用真实性校验保持现有约束；本轮不改 embedding、RRF、重排、分块、上下文预算或五步上限。其他方向仅在后续出现对应证据时再安排。

### 4.2 每次只解决一个已确认原因

从抽查中选一个影响明确的问题，写清对应题目 ID、失败阶段和修改假设，再动代码。同类重复出现的问题优先；单个可复现且严重的错误也可优先处理，不规定必须凑够几例。

按证据选择最直接的改动：例如查询没有表达关键条件，先调整查询；必要证据已经在重排池内，先检查排序损失；上下文因某条长片段挤掉关键材料，先检查选择规则。不能同时改 top-k、重排提示、合并策略和最终回答后，把所有变化归为 Agent 收益。

上下文改动继续尊重真实来源、版本、完整片段和当前引用约束。需要改变字符／数量预算时说明具体案例及开销影响，不直接截断原文冒充完整证据，也不默认扩大到更大窗口。分块变动会影响索引和入库，只有实际证据指向它时才处理，不用“重新切块试试”作为首选。

回答改动只在必要内容确实已进入最终输入后开展。可针对遗漏、证据与推断混写或主张引用错配调整已有提示；不增加每题额外模型自检或裁判。来源 ID、页码及程序 answered 均不能自动证明回答有用或有据正确。

### 4.3 五步 Agent 的观察与边界

保持最多五次自主决策及现有触顶收尾。分析实际检索次数、自主步数、网络重试／格式修复、触顶收尾和真实请求数，不将它们混为同一种“轮数”。

同查询同范围已有去重，先复用。不同范围使用同一查询可能有效；一次无新证据也可能需要改写查询，不能因此强制结束。只有轨迹显示反复无效行动时，才改善已有行动提示或工具观察的表达，不新增一套固定步骤。

观察后续步骤是否新增有用材料、这些材料是否被实际引用，以及最终回答是否改善。仅凭五步轨迹不能证明三步也能得到相同答案；若以后确实需要比较 3／5 步，应单独安排有明确目的的真实对照，不在首轮进行参数网格试验。

### 4.4 中文、跨论文与追问场景

QASPER 只支撑其单论文、单轮、英文子集结论。若选定问题涉及中文、跨论文或追问，优先复用现有项目案例和页面历史输入；不足时只补对应的少量开发例，新增总量以 4–6 例为上限，无须凑满。

每例记录问题、明确的论文版本、必要的前序对话及简短预期要点／支持位置即可，不重做大型标注集。沿用现有页面调用能力，不为几个场景扩建批量多轮框架。项目场景结果单列，不混进 QASPER Answer F1／Evidence F1，也不动原冻结验收集。

## 5. 改前、改后的观察方式

离线用例先确认实现行为；真实质量收益依赖另行授权的同题复测。复用已保存的改前基线，新版本使用同一批题、相同论文版本、生成模型、语言要求与未改动的检索／轮数条件，使用新的普通批次目录保存结果，不覆盖旧输出。

本轮真实局部复测限定为 D2-003、D3-002、D5-006、D6-004 四道失败题，加 D2-001、D2-002 两道已有正常题，现已在用户授权后执行完成。复用现有成对入口，共 6 题／12 份模式记录；对照结果与残留问题见开头，不默认继续重跑全部 20 题或 QASPER。

原始 20 题基线直接保留，6 题局部结果不能替换其分母，也不能据此宣称全体成功率提高。尤其 D2-003 必须有实际支持材料后再声称论文事实，D5-006 不以“必须搜到引用”为成功条件，另外两题需验证字段合法且引用约束未被绕过；仅改标签或静默补字段不算修复目标问题。

先在对应失败题和少量已有正常开发题上做局部复测，观察目标问题是否修复及有无相邻退化。需要总结样本整体效果时，再运行原先固定的 validation100，不反复拿这 100 题搜索大量参数，不提前使用 test 或原冻结验收集。针对失败题挑选的复测结果只能证明这些案例的变化。

共享检索或上下文改动会影响固定 RAG 和 Agent，应在同样的新条件下比较两者；Agent 专属改动不归因给固定 RAG。未变化的旧基线结果直接复用，保留两模式独立执行的实际成本口径，不通过共享首轮检索降低账面请求数。

至少说明目标失败是否解决、逐题及均值变化、退化案例、可比较题数和实际开销。Evidence F1 沿用 2.3 的 null／共同可评集合规则；改前与改后比较也使用同一可评题目集合并列出覆盖变化，不能把不同分母的均值当成提升。失败和未尝试仍按原口径保留。

不预设“提高几个点”或某个 F1 值作为必须达成的目标。若未见改善、出现明确退化或开销不合适，撤回本轮尝试或保留原方案，并按实际结果说明；不为得到正向结论连续叠加无关修改。模拟响应测试通过只能证明流程，不能写成真实质量提升。
