调用链为：模型返回 tool_calls → 按调用顺序执行现有检索 → 每个调用得到对应工具结果 → 模型读取累计证据 → 发布最终答案。

原生工具只负责 search。没有工具调用时，最终回答仍使用现有 AnswerAction／AnswerDraft JSON、claims、direct_answer 和 citation_ids，并复用 publish 的引用回查与保存流程；不把最终答案改为无结构纯文本，也不新增 answer 工具。带工具调用的响应先完成工具处理，不把其中伴随的普通文本直接发布为答案。

页面自主 Agent 接入新路径；问题理解与查询规划、固定 RAG，以及非自主模式已有文本回答调用继续使用原客户端的无 tools 调用方式。无需新建运行模式开关或兼容框架。自主路径不在工具调用失败后退回截取普通文本中的 search JSON。

### 3.2 错误反馈与原有额度

单个工具参数不合法时，返回可读的参数错误；现有检索失败或无结果时，回填真实失败或空结果。所有结果都对应原 tool_call_id，已经取得的证据继续保留。错误不算检索成功，也不凭错误结果生成可引用证据；鉴权、连接等模型请求错误继续由客户端按现有规则处理。

保留五步自主决策与原强制收尾机制。同轮多调用不得放大原来最多五次检索的上限：按剩余额度逐个执行，超过额度的调用回填额度已用完，不发额外 embedding 请求；额度用完后的生成关闭工具，只允许现有最终回答。复用既有步骤与检索记录计数，不增加通用预算系统。

工具参数错误通过后续自主步骤修正，不另加一轮专用模型审核；原来的最终答案格式／引用修复继续共享既有修复额度，不提高次数。工具协议定义、调用、执行、回填和最终发布必须同时接通，不能只给请求加 tools 参数。

## 4. 任务二：解释按方法阶段对应证据

在 [context.py](D:/course/paper-research-assistant/paper_assistant/context.py) 已有共享 ANSWER_ORGANIZATION_INSTRUCTION 中补充简短规则，由现有固定／Agent 消费路径共同使用：

- 描述论文机制时，明确其所属任务、模块或阶段；一个阶段使用某模型，不能推出整个系统或其他阶段都使用它。
- 原文事实与分析分开，分析中涉及的论文方法事实也必须有对应阶段的依据；标为 analysis 不能替代事实支持。
- 解释围绕所问内容展开。需要补充其他阶段的机制时，先取得相应原文；若没有，就不生成这项未获支持的技术说明。
- 跨论文比较沿同一维度分别组织两篇证据与引用，保留各自适用条件，不交换机制归属。

继续传递已有证据身份和章节信息，不为这一错误修标题层级、重新摘要全文或增加新的证据结构。规则不硬编码菜谱论文、word2vec 的正确答案或参考页码。按原方式更新受影响的提示版本标识。

这项改动的目标是改善同一次生成的忠实性，不能保证消除所有语义错误。最终输出原样保留，不靠事后删除错误 claims、改写模型原文或额外裁判调用取得通过结果。
