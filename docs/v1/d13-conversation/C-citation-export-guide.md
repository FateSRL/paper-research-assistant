### 同名历史对话与追问跳转修复（2026-10-09）

用户发现两个会话首问相同时显示名相同，继续追问会跳到另一个会话。已从本机 Streamlit 代码确认：selectbox 用格式化后的显示名传输选项，同名映射保留最后一项；页面又把当前会话放在首位，因此下一次提交的控件状态可能被解析成另一个会话。

只调整原选择器：会话按已有记录的创建顺序排列，不随当前选择或追问重排；每个名称都带对应序号，例如“对话 1 · 相同问题”“对话 2 · 相同问题”。仅当新对话／切版本确实改变当前会话时同步选择器，不再每次重绘无条件覆盖。没有增加模型命名请求、额外 ID、校验或哈希。

## 4. 问题与答案

**为什么弹窗同时显示原问题和完整问题？** 用户可以核对系统是否正确理解“它”或“第二条”，并确认眼前原文支持的是哪一轮、哪条结论。

**为什么切换论文后旧引用仍然正确？** 每个引用弹窗使用该轮已保存报告里的来源映射和版本，不使用当前选择或最新回答重建来源。

**导出近期历史是否就是全会话导出？** 不是。本轮 Markdown 只展示 B 实际使用的有限窗口，完整 JSON 也沿用该轮记录；没有新增全会话汇总功能。
