# 回答组织与引用展示修改日志

完成日期：2026-10-09。完成用户批准的前两项：连贯回答组织、正文与引用入口展示。

## 第一项：按问题组织回答

交付：`context.py` 与 `agent_prompt.py` 共用回答组织指令。先直接回应问题，再按概念、过程、原因或比较关系组织正文；同主题、同依据的信息组成连贯段落，避免按检索排名逐片段介绍、重复开场或无关章节罗列。简单问题通常两三段，详细问题可使用 Markdown 小标题或必要列表；段数只是写作指导。

保留原 `claims / basis / citation_ids` 结构，一条 claim 可以承载多句段落，不同依据继续分开。引用只取实际使用的证据，显示编号交给页面生成。现有提示版本标记更新为 v2，固定 RAG 的来源限定版本记录同步更新。

验收：扩展并运行既有 `ContextChecks.test_model_messages_show_only_selected_content_and_data_question`，确认 RAG 与 Agent 两阶段收到共享指令，展示证据和动作契约保持一致，多句段落通过原草稿结构。首次新增测试误将 `AnswerDraft` 当字典读取，改为 `model_dump()` 后只重跑该方法，通过，1 个测试、0.058 秒。

取舍：直接在原回答调用中组织内容，保留原短修复流程，不增加润色调用、结构字段、段数校验或哈希。此次离线验证覆盖消息构造与结构，真实生成的语言效果由后续问答体验判断。

## 第二项：正文与引用分开显示

交付：`app.py` 使用普通 Markdown 展示保存的段落，支持正文内的小标题、强调和列表。原整段引用按钮改成段末紧凑编号入口，如 `[1]` 或 `[2] [1]`；编号按本轮首次使用来源的顺序分配，相同来源复用编号。多来源段落的一个入口展示该段实际引用的各条原文，各自保留一致编号、论文信息和 PDF 文件页序；分析引用仍说明是分析前提。

无引用的模型知识、分析也用正常正文显示，依据说明放在段落之后。失败时先显示简短状态，检索原文默认收在“查看本轮检索到的原文”；展开后照常查看。真实错误状态、用量和下载继续保存在详情中。侧栏、欢迎页和 README 操作说明同步改为点击引用编号。

验收：只扩展并运行以下两个既有方法，合计 16.966 秒，通过：

- `PageChecks.test_two_modes_five_terminal_states_and_full_citations`：两模式与五类终态、普通 Markdown 正文、多个来源融合成一段、相同来源编号复用、原文与页码对应，以及失败资料默认收起。
- `PageChecks.test_saved_mode_query_pairs_survive_control_changes_and_reruns`：历史切换、追问与重绘后仍回查各轮保存的原文，没有再次提交问答。

另外用临时 Streamlit 页面和模拟问答检查实际浏览器：正文、Markdown 小标题、紧凑引用入口正常；点击 `[2] [1]` 显示第 3 页与第 2 页对应原文，问答计数不增加；模拟失败资料默认收起，展开可查看原文。临时服务、标签页和脚本已清理，保留一张离线展示截图供查看效果。

取舍：使用现有 Streamlit Markdown 与 popover，没有新增组件依赖、引用解析器或正文／引用映射校验。
