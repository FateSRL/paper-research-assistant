# D9 D：离线故障边界与自检

执行日期：2026-10-06。完成记录见 [task_d.json](/D:/course/paper-research-assistant/artifacts/d9/task_d.json)，当前报告见 [d_boundary_validation.md](/D:/course/paper-research-assistant/artifacts/d9/d_boundary_validation.md)。

D 验证的是：来源不合格、文件损坏、超时、修复失败或导出冲突一起发生时，程序是否仍能正确停止、保留已经发生的费用，并防止发布不合格答案。模拟模型响应是预设数据，不能作为新版本答案准确率。

检查复用适用的 B/C 与固定 RAG、Agent、检索、成对和导出检查，并新增 12 项必要组合。方法数按实际 unittest 方法计；一个方法中的多个 subTest 不另计。C 的 32 项与 317 项兼容检查已经包含在 D 覆盖范围中，不能再相加。

你先理解这五件事就能读报告：

1. **来源资格**回答“这个完整片段是不是核定摘要”。第 1 页正文不算摘要；第 2 页的真实摘要可以合格；跨出核定区间的 mixed 片段不能因含有摘要文字而合格。
2. **引用检查**逐条检查实际引用。一个结论同时引摘要和正文，正文引用仍须过门槛；共享修复后仍越界就不能发布。
3. **新召回与新展示**分别表示搜索拿到了新片段、模型实际看到了新证据。新片段超过完整片段字符预算时，可能召回了却不能展示；此时 Agent 停在 `no_new_shown_evidence`，不再付费问最终聊天。
4. **剩余时间**是原 120 秒减去已耗时间。发送前耗尽算 0 次；发送后失败算实际尝试，已知 tokens 保留，未知用量写 null。提交前关闭资源或核对文件时过期，成功也会转为预算耗尽。
5. **业务提交与导出**是两个边界。提交后的导出失败保留原业务结果用于诊断和账本，页面按失败状态展示，不能把诊断中的成功答案发布出来。

真实 Registry/PDF/SDK MockTransport 组合覆盖了来源文件与原文损坏、摘要资格/伪造字段与过期、引用修复与过期、PDF 核验故障与过期、补查/两模式之间范围表漂移、原生 scoped ready/向量查询与过期，以及新召回但无新展示停止。其余已有边界按生产检查类重跑，详细对应关系在 JSON 的 `coverage_mapping` 中。
