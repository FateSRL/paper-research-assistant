# D11 执行计划：论文信息、缺口化补查与有效正文

制定与完成日期：2026-10-08（Asia/Shanghai）。**D11 A–C 已完成实现，下一步 D12。** 本阶段编号表示实施顺序，不绑定原两周日历。总规划已将新增三组功能安排为 D11–D13，首次最终验收顺延到 D14。本轮 3 个相关现有测试方法通过，未新测真实模型效果，D10 旧成绩不归为 D11。

## 1. 目标与依据

针对已保存的“介绍一下这篇论文／这篇论文讲了什么”失败：首轮可能只有 `Abstract`、`Introduction`、作者姓名或零碎表头；二轮如果仍搜索“摘要、方法、贡献、结论”，缺少具体论文主题，容易再次取回无用片段。带 `retrieval-augmented generation`、`RAG` 等主题词的历史查询已经取得正文，但这些单次观察不能证明新方案必然答对。

本轮在现有 Agent 的“搜索 → 判断缺口 → 一次补查 → 引用回答”中完善查询和证据输入，不增加独立分类模型、额外补查轮数或 RCS 模型调用。题号、标准答案和期望 chunk 只用于事后定位，不传入问答流程。

## 2. A–C 任务清单

| 任务 | 实施内容 | 结束条件 | 状态 |
|---|---|---|---|
| A：论文信息 | 从已有所选论文及解析版本读取标题；提供实际可用的摘要原文和来源位置，不生成或冒充元数据摘要 | 摘要出自真实解析内容，作为补查背景；相关原文进入实际展示后才可引用 | 已完成实现 |
| B：缺口化补查 | 在现有决策提示中结合原问题、论文身份和已读内容生成 `missing_information` 与 `retry_query`；查询带实际主题/术语，并与正文语言一致 | 继续使用现有一次 `retry_search`；针对缺口而非只改写原句；无新增分类或摘要模型调用 | 已完成实现 |
| C：有效正文 | 命中摘要、章节标题等零碎片段时获取对应正文或必要邻接 chunk；根据问题保留有效证据，作者问题可保留姓名 | 展示和引用对应实际原文；不跨出所选论文/版本，不将未展示文本当作本轮依据；正文仍受现有上下文上限控制 | 已完成实现 |

A/B/C 独立日志已保存：[A 论文信息](/D:/course/paper-research-assistant/docs/v1/d11/d11-A-paper-context-guide.md)、[B 缺口化补查](/D:/course/paper-research-assistant/docs/v1/d11/d11-B-retry-query-guide.md)、[C 正文获取与实际验证](/D:/course/paper-research-assistant/docs/v1/d11/d11-C-evidence-body-guide.md)。各日志含学习入口和 3 个关键问题答案，C 集中记录 3 个现有方法通过及旧失败候选的只读正文回放。本轮没有真实模型/embedding 请求或新增答案成绩。

## 3. 实施范围与验证

- 复用 SQLite 元数据/原文、Qdrant 向量和现有 Agent 消息、动作、预算、引用定位。无需重新解析三篇论文或生成已有正文向量。
- 概述需求由现有 Agent 结合问题和论文内容判断，不另建关键词路由或分类模型。检索候选的正文处理面向证据用途，不统一删掉姓名或短片段。
- 一次补查、共享三次聊天尝试、最终最多 8 条证据/8000 字符和来源范围继续约束本轮；具体实现以实际日志为准。
- 普通小改动选择 1–3 个能覆盖改动的相关现有测试方法，不按整个目录运行；测试失败或发现具体跨模块影响才扩大。已通过且代码未再变的结果直接复用，文档不跑测试。
- 离线验证不调用真实模型或 embedding，不安排额外整批 D10 重跑、验收执行、哈希快照、审计脚本、独立验证报告或付费裁判。
- D11 仍遵守当前原文回答规则。允许模型知识、无引用回答与前端依据标记属于 D12，不混入本阶段。
