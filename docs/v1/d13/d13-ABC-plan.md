# D13 执行计划：BM25＋向量＋RRF 混合检索

制定与完成日期：2026-10-08（Asia/Shanghai）。**D13 A–C 已完成实现，下一步 D14 首次最终验收。** 本阶段承接 D11 的主题化补查和正文获取、D12 的不足时仍回答与逐条依据；增加本地关键词召回与两路融合。3 个相关现有离线方法通过，未新测真实模型效果。

## 1. 目标

在同一查询、同一选定论文/解析版本范围内，同时获取向量语义候选和 BM25 词项候选。两路各最多 20 条，按 chunk ID 去重，以 `sum(1 / (60 + rank))` 融合；排名从 1 开始。融合后按调用入口原有 `top_k` 返回，问答仍 top-5，不把 40 条候选全部塞给模型。

向量检索能覆盖表达相近但用词不同的内容，BM25 能补充方法名、缩写、指标名等词项命中。RRF 使用两路名次，避免直接相加两种不同尺度的分数。这个机制增加召回途径，实际回答效果须由后续保存输出评价。

## 3. 实施边界

- 使用 SQLite 中已有 chunks，不重新解析、分块或生成正文向量，不引入检索服务器或新的第三方依赖。
- BM25 对正文词项评分，不自动翻译查询；英文词项统一大小写，中文采用相邻双字词项。D11 的补查查询仍负责选择论文主题和正文语言。
- 同一个 searcher 生命周期内缓存相同论文/版本组合的词项处理，避免 Agent 补查重复处理相同正文；不新增磁盘索引、hash 或更新扫描。
- 摘要限定的 `allowed_point_ids` 同时过滤向量和 BM25 候选，不能用关键词路径绕过来源范围。
- 首轮展示 5 条、Agent 最多一次补查、最终最多 8 条/8000 字符、共享聊天与时间预算保留；不加入独立 reranker、RCS、HyDE 或意图分类。
- 普通小改动选择 1–3 个相关现有方法；只有失败或具体跨模块影响才扩大。文档不跑测试，离线不调用真实模型/embedding；本轮不运行 D14 原 20 题验收。
