# 页面问答兜底与调用限制调整日志

完成日期：2026-10-09。根据实际 Raft 两轮失败调整页面问答，原 D14 验收安排保持。

同日后续：回答已改为连贯段落与段末引用编号，失败时检索原文默认收起，见 [回答组织与引用展示日志](/D:/course/paper-research-assistant/docs/v1/answer-paragraphs-guide.md)。以下自动展开及验证记录保留为此前实现时的事实。

## 实际原因

18:20 的详细解释先执行追问补全、Agent 补查判断和补查后回答，第三次输出达到 1200 token 被截断；准备修复时共享三次请求已耗尽，最终为 `budget_exceeded/request_limit`，整轮约 30.45 秒，并非时间超时。18:21 的简单解释在首次回答和修复时都达到 1200 token，最终为 `invalid_output/truncated`。两轮尚未进入引用检查。

## 实际修改

页面 `library_mode` 使用 4096 输出 token，取消整轮三次聊天和 120 秒硬限制。继续保留单次聊天请求最多 30 秒、本机配置中更小的单次超时、既有最多一次网络重试／格式或引用修复，以及 Agent 最多一次补检索；流程由这些有限步骤结束。请求次数与用量继续如实记录。默认 CLI 和冻结评测的 1200 token／三次／120 秒策略保持。

正常输出要求紧凑 JSON、避免重复内容和多余引用 ID，同时保留用户所需详细程度。Agent 和固定 RAG 在 `truncated` 时复用原一次修复，要求重新生成完整短答：最多四条核心结论，每条一至两句，必要说明最多一句，保留完整来源 ID。没有新增重试层或不完整 JSON 拼接。

若仍不能生成可发布回答，页面主区先展示实际检索到的原文并自动展开，不把未完成输出伪装成答案。无原文时给出可重新发送／拆分问题的提示；具体状态和错误代码收在“回答详情与下载”。原报告状态、原文、请求和用量保留，下载不改变失败记录。

取消整轮时限的策略在报告中保存为 `null`，原 `deadline_checked` 字段为 false；内部无限剩余时间不会写入 JSON。没有新增哈希、审计、通用校验或额外引用规则，也未重建向量。
