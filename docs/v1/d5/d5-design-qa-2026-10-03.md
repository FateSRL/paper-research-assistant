## 2. 产品与机制（已实现部分的事实陈述）

**产品定位**（总计划原文）：带证据回查和受控补检索能力的论文调研助手。解决三个问题：找到候选论文、针对选定论文提问、快速回到原文核对答案。首版限定 1–3 篇文本型英文 PDF。

**形态**：现在为 CLI `scripts.answer_question`；D6 计划接入 Streamlit，复用 `rag.py`，不复制业务逻辑。D8 计划加入 `retry_search` 一次补检索。

**机制六组**（均已在 D4/D5 A–E 实现）：

| 组 | 内容 |
|---|---|
| 版本与身份 | 三层身份（论文版本 / `parse_revision` / `index_profile_id`）严格分开；不可变快照；确定性 chunk 与 point ID；唯一约束 + ready 状态机共同保证幂等 |
| 检索 | 一次问题 embedding，完整 `(paper_id, parse_revision)` 配对过滤，top-5，候选回 SQLite 核验原文与来源 |
| 生成 | 允许引用集合 = **本轮实际展示的 `shown_text` 快照**（字符区间 + sha256）；版本化提示词；严格 `AnswerDraft` JSON；`EvidenceRef` 由程序回填 |
| 校验与状态 | 结构合法 / 引用定位合法 / 语义支持 / 系统故障四层分离；五终态 `answered`、`insufficient_evidence`、`tool_error`、`invalid_output`、`budget_exceeded`；有界修复一次，修复失败不发布答案 |
| 预算与可观测 | 请求计数下沉到 SDK 尝试层（显式关闭隐式重试）；共享三次预算；30 秒单次、120 秒整轮；不可覆盖运行记录；日志脱敏 |
| 验证纪律 | 程序边界检查与问答质量集分开统计；人审继承需版本、样本、来源、材料全部一致；验收记录绑定源码 SHA |

## 3. 拒答设计的讨论与结论（本次主要产出）

### 3.1 起点

提问：如果用户问了与论文无关的内容就拒答，是否过于死板？论文内容本身也可能牵扯其他内容。

**三种问法必须分开**，当前被同一套逻辑处理：

| 类型 | 例子 | 当前行为 | 应有行为 |
|---|---|---|---|
| 论文里有 | "RAG 用了哪两类记忆" | 带引用回答 | 保持 |
| 论文里没有但与论文相关 | "这篇提到的 BERT 是什么" | 拒答 | **真正的痛点** |
| 完全无关 | "今天天气" | 拒答 | 拒答正确 |

### 3.2 方案演进

**方案一：一次请求内输出两段**（第一段带引用、第二段为通用知识）。

否决理由：提示词无法强制分区，必须落在数据结构上；且模型一旦知道存在兜底，就有动机把"其实论文里有"的内容判为证据不足，从而绕过引用机制。

**方案二：级联（第二段独立调用）**

可行性结论与路由规则：

| 第一段终态 | 是否进入第二段 | 总聊天请求 |
|---|---|---|
| `no_hits` | 是 | 1 |
| `insufficient_evidence` | 是 | 2 |
| `answered` | 否 | 1 |
| `invalid_output` | 否 | 1–2 |
| **`tool_error`** | **绝对不可** | — |
| `budget_exceeded` | 否 | — |

补充约束：第二段只允许持有问题与选定论文**标题**，不得持有检索到的正文（否则等于绕过引用校验）；第二段不得计入问答质量指标；新增失败类型"错误回退"（论文里其实有却走了第二段）需单独统计。

**方案三（最终结论）：砍掉第二段，改为"有信息的拒答"**

理由：第二段与普通大模型无区别，是**整个项目中唯一没有护城河的部分**，可被一句话复制；同时新增失败面、稀释"每句话可回查"的产品承诺。

替代方案为**有信息的拒答**——拒答时告知本系统独有的信息，全部为 0 次 API：

- "这三篇里没有依据，但检索到 3 条相关片段，位于第 5 页、第 12 页，可自行查看"（数据来自本轮候选与展示证据快照）
- "缺的是关于 X 的信息，选定论文里没有；是否将某篇加入语料"（数据来自语料边界与模型给出的 `reason`）
- "附一段通用助手入口链接"，明确标注为跳出本产品，不进运行记录、不进评测

**现状核对**：`SYSTEM_PROMPT` 已要求 `insufficient_evidence` 时输出 `reason`（"Explain what the shown evidence lacks"），即"有信息的拒答"已完成一半，尚未在界面上利用。

### 3.3 与公开实现的一致性

2026-10-03 公开检索（见 §6）显示：Abstention Recipe 明文规定拒答须说明搜了什么、没找到什么，可选附一条标注过的最近似结果，且**绝不静默回退到通用知识**。本次讨论独立推出的结论与该指引一致。

## 4. 置信度阈值弃权（T_abstain）

**机制**：在检索打分之后、调用模型之前设置数值闸门。检索到的公开实现指南中，其为并列五条件之一：

```
mean(top-N chunk confidence) < T_abstain   （默认 0.45）
或 检索结果为空 / 候选互相矛盾 / 查询超范围 / 内容过期
```

**业界采用理由**：省一次模型调用、结果确定、大规模下必要、多租户防滥用。属规模与成本取舍，不是错误做法。

**本项目明确不用**，依据总计划 §4 原文："不靠一个相似度阈值证明'证据足够'。高相似度片段可能没有答案，模型也可能误判是否需要补查，这些都交给后续评测检验。"

三条硬伤：

1. **分数不校准**：同一数值在不同 embedding 模型、语料、问题长度下含义不同，默认值属魔法数字；可能出现闸门恒开或恒闭。
2. **高相似 ≠ 有答案**：同主题但无所需事实的段落分数不低。ReAct 摘要题为实例——top-5 分数不低，但其中没有摘要依据，闸门会放行。
3. **低相似 ≠ 没答案**：措辞特殊的可答问题可能被误杀，直接制造"错误拒答"。

**替代**：由模型阅读实际正文判断充分性，并对判断质量做事后测量（错误拒答 / 正确拒答分别统计）。

**若未来引入的正确姿势**：在本语料上标定阈值（用开发集分数分布，不沿用默认值）；只作路由信号，不作充分性证明；必须测量其对错误拒答的影响并与基线对照。

## 5. 当前判定机制（代码事实核对）

**不是取最高分，是 top-5 全部交给模型。** 相关常量：

```
SELECTION_VERSION = "rank-deduplicate-full-chunks-stop-v1"
PROMPT_VERSION    = "d5-evidence-answer-v1"
```

- `score` 不参与任何判断，仅被记录进快照；`rank` 只用于稳定排序与到达字符预算时的取舍。
- 判定分三层，无一使用分数：
  1. **程序**——检索返回空 → `no_hits`，直接返回不足，不调用模型；
  2. **模型**——阅读拼成 JSON 的完整正文，返回 `answered` 或 `insufficient_evidence` + 缺什么；
  3. **程序**——校验引用是否属于本轮展示集合、真实存在、版本/页码/哈希一致。
- `SYSTEM_PROMPT` 已包含三条防线：相似度是排序信号而非置信度；禁止使用外部知识与未展示段落；`insufficient_evidence` 表示"本轮缺证据"而非"论文没有相关内容"。
- **判断准确性目前无任何测量**，`semantic_support_status = not_reviewed`，属 F 的任务范围。

| [EvidenT](https://arxiv.org/pdf/2609.22537v1.pdf) / [dokis](https://pypi.org/project/dokis/) / [Houndex](https://pypi.org/project/houndex/) / [Grounded](https://github.com/ncecere/grounded) | 逐条 claim 对照原文、n-gram 重叠检测引用漂移、`audit(query, chunks, response)` 校验、不可变审计 |

**结论**：

1. 引用校验、拒答分区、审计轨迹、终态区分**均非本项目原创**，部分有开源实现。
2. 本项目在设计完成后才检索到这些实现，属独立收敛到同一处；可在面试中如实表述，不得声称首创。
3. 公开实现普遍**只校验引用定位合法性，不校验语义支持**——与本项目"引用定位合法 ≠ 语义支持"的区分一致，而本项目把该区分显式写入契约与状态。
4. 需注意：上述为 2026-10-03 检索所见，产品行为变化快，具体能力以各自官方为准。

## 7. 项目客观定位

**结论：不是 toy，是一个窄而深的垂直切片。** 玩具指"演示概念但不做真实决策"；本项目在架构与不变量层面做的是与工业界同构的决策，只是规模停在 demo 层。

| 维度 | 本项目 | 工业界 | 个人可关闭 |
|---|---|---|---|
| 检索质量 | 单轮 dense top-5 | hybrid + cross-encoder 重排 + 查询改写 | 可以，数天至两周 |
| 评测 | 16 题手工 | 数百题 + 标注一致性 + 统计显著性 + CI 回归门禁 | 部分，人力密集 |
| 服务层 | 同步 CLI，单进程 | 流式、并发、缓存、p99、按租户限流计费 | 可以，数天 |
| 入库鲁棒性 | PyMuPDF 文本层 + 人工 bbox 规则 | OCR、版面模型、表格抽取、增量重建、失败队列 | 部分，以月计 |
| 规模与多租户 | 3 篇、单用户、本地文件 | 百万文档、分片复制、ACL、租户隔离 | **不可，属组织问题** |
| 可观测 | 磁盘 JSON 记录 | tracing、指标面板、告警、灰度 | 可以，数天 |
| 模型层 | 单提示词、单模型 | 模型路由、约束解码、蒸馏、越狱防护 | 部分 |
| 安全合规 | 日志脱敏、注入防护提示 | PII、数据驻留、SOC2、WORM 审计 | **不可，属组织问题** |

**同构且可迁移的部分**（属判断力，非知识）：检索失败与生成失败分开归因；"引用合法" ≠ "结论被支持"；请求计数下沉到 SDK 尝试层；离线边界测试不混入质量指标；评测集先冻结再看结果；已知失败保留而不静默修复。

**本次提出的主要批评**：努力分配偏斜——绝大部分精力用于记录、验证与文档，检索质量仅为单轮 dense top-5 且保留已知漏召回。工业界顺序通常相反：先做检索质量，再上仪表。若继续发展，下一投入方向应为检索质量而非更多文档。

## 8. 检索质量：定义与调整方向

**定义**：可回答问题中，人工标注的关键依据出现在本轮展示证据里的比例，即 **hit@5**（对应总计划 §7.3 的"关键依据检索命中数 / 可回答题数"）。当前仅有 2/3 的三题观察，样本不足。

**天花板关系**：

```
可答题回答准确率 ≤ 检索命中率
```

由于 `SYSTEM_PROMPT` 禁止使用外部知识与未展示段落，**未进入展示集合的段落等于不存在**，检索漏召回必然导致答不出或拒答。一般 RAG 系统可被模型先验知识部分掩盖，本项目没有这层缓冲，检索质量直接等于产品上限。

**调优旋钮（按性价比排序）**：

| 顺序 | 手段 | 成本 | 说明 |
|---|---|---|---|
| 1 | 提高 top-k（5 → 10/20） | 半小时 | 现有 8000 字符预算未被用满；最便宜的实验 |
| 2 | 重排 reranker | 1–2 天 | 粗捞 50 再精排出 5；单项提升通常最大 |
| 3 | 混合检索（向量 + BM25/sparse） | 1–2 天 | Qdrant 原生支持 sparse；治专有名词、缩写、精确短语 |
| 4 | HyDE | 半天（多一次模型调用） | 治问句与陈述句的形状不匹配 |
| 5 | 章节元数据（`section` 字段） | 需重解析 | 直接对应"摘要"来源限定问题；当前 chunk 无该字段 |
| 6 | 邻居扩展 | 半天 | 治答案被切在块边界 |
| 7 | 改分块参数 | 1–2 天 + 全量重建 | 最后手段；产生新 `parse_revision` |

**ReAct 摘要题（rank 9）的病因与对症解法**：摘要段落用词通用、不带具体实验细节，在 dense 空间中与各正文段相似度居中，被更"具体"的段落挤出。对症排序：重排（cross-encoder 能同时读问题与候选，"这是摘要段"这一信息 dense 看不见）> 章节元数据（物理上不可能漏）> 提高 top-k（rank 9 意味着 top-10 即可捞到）。

**纪律要求**（沿用本项目既有规则）：先冻结基线再改动；一次只改一个变量；改 embedding 配置产生新 `index_profile_id`，改分块产生新 `parse_revision`，不覆盖旧索引；每个改动与基线对照并写成可解释的新实验；当前题量下（16 题）一题翻转即 6 个百分点，只能识别大效果。

**优先级提示**：以上调优均排在 F 与投递之后，不构成 D5 前置条件。
