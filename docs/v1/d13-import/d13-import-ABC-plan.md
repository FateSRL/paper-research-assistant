# D13 后新论文入库补充：A–C 执行计划

制定日期：2026-10-09（Asia/Shanghai）。**A–C 已实现并通过针对性离线验证，下一阶段 D14。** 入库服务、新论文问答、摘要范围和本地原文回查已接通；页面提供 PDF 上传、后台局部进度、失败重试及论文列表刷新，模拟服务下的真实浏览器流程已通过。独立日志见 [A](D:/course/paper-research-assistant/docs/v1/d13-import/A-import-guide.md)、[B](D:/course/paper-research-assistant/docs/v1/d13-import/B-runtime-guide.md)、[C](D:/course/paper-research-assistant/docs/v1/d13-import/C-upload-guide.md)。用户可在现有页面上传一篇文本型 PDF，后台完成入库，随后直接选择它进行固定 RAG／Agent 问答、连续追问和原文回查。作为 D14 前的功能补充，D14–D17 不重新编号。

## 1. 现有能力与实际缺口

已有 `ingest.parse_pdf_pages()`、`quality.filter_paper_pages()`、`chunking.build_chunks()`、`PaperStore.import_version()` 和 `IndexBuilder.import_version()`，可以复用解析、过滤、分块、存储、embedding 缓存、向量写入及 ready／failed 状态。

规划时缺少以下三个环节，现已由 A–C 补齐：

- 新 PDF 需要手工登记 `eval/corpus.json` 并分步执行脚本；页面没有上传入口。本地非 arXiv 论文还会被存储、论文列表和引用读取中的 arXiv 字段规则拒绝。
- 页面列表已经从 SQLite 读取 ready 版本，但 `d9_runtime.run_question()` 仍以 D9 固定三篇的配置白名单检查提交，新论文会出现“选得到、问不了”。
- `source_scope.Registry` 要求所选版本存在于旧 D9 来源表；新论文缺记录时，普通正文问答也会失败。

只补齐这条使用流程。上传不修改固定评测语料 `eval/corpus.json`，不自动改写历史实验配置或旧三篇的来源范围。

## 2. 用户操作与任务划分

```text
侧栏“添加论文”：选择 PDF，可填写标题
  → 点击“开始入库”
  → 局部显示：解析 → 分块 → 生成向量／写入进度
  → 成功：更新论文列表，用户选择新论文
  → 沿用现有问答、连续对话、引用弹窗与下载
  → 失败：显示失败阶段，用户可点击重试
```

标题默认使用文件名，外部来源链接可选；不调用模型提取元数据。选择新论文沿用现有“论文集合变化时开启新对话”的行为，入库完成本身不强制切换用户正在看的对话。

| 任务 | 必要工作 | 完成标志 | 状态 |
|---|---|---|---|
| A：本地 PDF 入库 | 用薄编排串联现有解析、过滤、分块、SQLite 和向量入库；支持真实本地来源；复用重复导入与失败重试 | 一篇新 PDF 无需维护评测清单即可成为 ready；重复提交复用原版本与已有向量；失败不作为可问答论文 | 已实现，两个相关既有方法通过 |
| B：新论文接入问答 | 页面问答使用当前数据库的 ready 版本；接通新论文来源、摘要范围、元数据及引用读取 | 新论文在两模式中可问正文、追问和回查；明确摘要问题按真实摘要范围处理；旧论文与旧引用仍可用 | 已实现，运行时和页面方法通过 |
| C：上传页面与进度 | 增加上传和开始入库按钮，后台执行并局部显示进度、结果和重试；刷新论文选择列表 | 页面无需手动跑命令即可完成上传到问答；入库时仍可查看已有对话和引用，页面重绘不会再次入库 | 已实现，既有页面方法和模拟浏览器流程通过 |

## 3. A：复用底层，不继承旧审计流水线

- 在一个小的入库服务模块中直接调用现有函数，不由页面拼接命令或启动旧 D4 脚本。
- 本地论文生成安全的 `local_` 标识，原 PDF 按内部标识保存，避免同名文件互相覆盖。标题和本地来源真实记录；没有 arXiv 版本或外部链接时允许相应字段为空，不伪造 arXiv 信息。针对性调整 `storage.py`、`web_runtime.py`、`citations.py` 的相关规则和必要展示。
- 复用已有 PDF 身份字段查找重复上传。已完成的相同 PDF 直接返回已有论文；未完成的导入继续使用原论文／解析版本及 embedding 缓存，不新增查重哈希。第一版不提供重新解析或版本管理界面。
- 保存原 PDF、逐页解析文本、过滤文本和 chunks，保留真实页序和原文字符位置。使用 `build_chunks()` 和现有 `StoredVersionInput`，仅提供存储消费者所需的版本信息。
- **新上传不调用旧 `prepare_chunk_version()`／`save_chunk_version()`／`load_chunk_version()` 整套快照流程**，避免为每篇论文复制 Python 源码、生成源码哈希和全部文件哈希清单。旧脚本和旧数据格式继续兼容，不在本任务里重构它们。
- 复用 `IndexBuilder.import_version()` 的批次进度、缓存和 ready／failed 状态。来源文件及 B 所需的版本信息在向量导入完成前准备好，之后才向用户宣布成功；不再另建一套就绪状态。
- PDF 无法打开、需要密码或过滤后没有可索引文本时，直接给出对应原因并停止，不请求 embedding。纯扫描 PDF 的 OCR 暂不纳入。

## 4. B：接通当前运行时与来源

- 页面问答采用当前 embedding 配置对应的 SQLite ready 集合检查所选 `(paper_id, parse_revision)`；复用已有 ready 读取逻辑，不扫描全库向量或重新生成配置哈希。
- 页面入库版本入口与原批量评测的冻结范围明确区分。旧 CLI／批量评测默认路径继续使用原冻结版本，不因用户上传自动扩充或重跑评测；两条路径共享原问答核心。
- 旧三篇继续读取既有来源表。上传版本从自身保存的过滤文本、chunks 和版本信息构造来源，不运行仅为旧三篇编写的来源表生成脚本，也不要求用户额外制作截图或人工审核材料。
- 按可定位的 `Abstract`／“摘要”标题和后续章节边界记录真实摘要字符区间，将范围放在已有版本信息中。边界无法确定时保留空范围，普通正文问题仍可问；明确限定摘要的问题沿用现有“摘要范围不可用”处理，不把首页或正文冒充摘要。
- 新摘要范围直接使用实际片段及字符区间，不新增摘要哈希；旧范围已有字段继续兼容。摘要背景只使用可定位的原文，不调用模型生成摘要。
- 新论文继续接入现有 BM25／dense 融合、重排、固定 RAG／Agent、连续对话及逐轮引用。原 PDF 和旧版本不被新上传覆盖，旧回答继续使用自身保存的 `evidence_sources`。

## 5. C：前端交互

- 在现有侧栏加入单篇 PDF 上传、可选标题／链接和“开始入库”按钮。只有用户点击开始才运行；提示入库会使用 embedding 额度，不添加二次确认流程。
- 复用现有后台 Future 与局部 fragment 的处理方式。工作线程只处理已固定的参数，进度经普通线程队列交给页面线程展示，不在后台访问 Streamlit 会话状态。
- 显示实际阶段和已有批次计数，例如“生成向量 30／120”；不虚构整体百分比或剩余时间。成功显示论文标题，失败显示发生阶段和重试按钮。
- 同一页面入库与新问答共用忙状态，避免同时打开本地 Qdrant；等待时仍可查看已保存回答、引用和历史对话。不新增任务调度平台、多用户锁服务或后台队列系统。
- 重绘不重复消费一次点击；重试是用户的下一次明确操作，复用原导入材料。完成后重新读取论文列表，不自动替换当前论文选择和会话。
