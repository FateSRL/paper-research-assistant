## 5. 练习与参考答案

### 题 1：冻结版本是不是必须新建文件锁、哈希清单或配置副本？

**参考答案：**不是。本项目这次冻结是“D11 使用已说明的同一版本和配置”的约定。冻结正文记录完整开发批次、实际提示版本、公开参数、策略、语料/索引、来源范围和评分输入即可。本次没有添加锁、全仓哈希或快照；现有 runner 的记录也不能单独证明未来源码永远不变。后续确需改动，应说明新版本及其对应批次。

### 题 2：D10 A/B 改了什么，F 为什么没有继续修改？

**参考答案：**A/B 只改现有 Agent 系统提示和两个提示版本常量，要求比较、机制及多部分问题覆盖原问题，缺证据且有用的补查被允许时补查。D/E 的证据显示 D2-002 Agent 已补查并完整、有据地回答两机制，因此该目标解决。D3-004、D6-003 的语义问题被明确保留，不能拿旧成功答案或未引用材料掩盖。F 选择直接固定本次完整版本，没有为了执行 F 而再增加功能或请求。

### 题 3：哪些信息可以写进冻结正文，哪些不应写进去？

**参考答案：**可记录模型名称、温度、token 上限、超时、请求次数限制、top-k、证据上限、论文处理版本、profile、来源表和批次 ID。这些说明实际采用的公开运行条件。API key、授权 token 等秘密不属于公开复现参数，继续保存在本机配置中，不写进日志或冻结正文；学习这些参数也不需要读取密钥。

### 题 4：Agent 有 17 个 `answered`，为什么严格正题完成只记 15/17？

**参考答案：**`answered` 表示程序发布了答案，不保证每条结论完全受实际引用支持，也不保证原问题全部要求已被证实。E 发现 D3-004 的实验归属没有被实际引用独立证实，D6-003 第 2 条结论存在训练数据生成者归属歧义，所以这两题没有计入严格完整有据的分子。它们仍在 17 道可答题分母中。负题合理拒答另记 3/3，不能相加后冒充正题满分或普遍准确率。

### 题 5：总 tokens 为 `null`，已知 106692，且人审 pending，应该怎么报告？

**参考答案：**分别报告原总量 `null` 和已知小计 106692 tokens，不将未知当作 0，也不强制用小计覆盖原总量。按已保存的请求记录说明聊天 SDK/HTTP 次数，不凭 `null` 推测漏计了付费调用。成绩应注明是 AI 对本批开发输出的事后语义观察；人审 pending 表示用户尚未提供新答案对应的人审确认，不能写成人工准确率或已验收通过。
