### 4.2 N07：先从已读证据连续性与准备覆盖入手

原问是如何针对中文特点调整资源。最终回答的部分标注规则有据，但漏掉结论明确列出的删除 AltLexC／新增 Progression。进一步阅读 [原始 JSON](../../archive/run_logs/d9/agent_20261026_074957_220040_0df00fc8fb29.json)后，责任范围比最初的“关键段落未进入最终窗口”更明确：

| 后续两次 read_context | 读取论元和关系章节，当前窗口优先呈现 `p3_c5`、`p3_c6`、`p4_c1`、`p2_c3`、`p1_c1` |

| 准备与最终 | 历史工具消息留下 `returned_ids/shown_ids`，未留下该结论正文；最终完整请求也不含该正文。准备给出 `answerable=true`，同时写“未完整列举”，最终未补出两项主要适配 |

因此，这个案例不能简单解释成“搜索没找到”或“最终看到答案却不使用”。更直接的切入点是：新增阅读如何改变原问所需证据的保留，早期原文为什么没有进入有效后续历史，以及准备完成的判断是否与原问覆盖一致。当前缺口描述偏向笼统的“没有穷尽”，没有识别先前已经读过却后来丢失的主要事实。

RAGFlow 的可借鉴方向是同一次 Agent 循环中延续已提供正文及其来源关联，使后续阅读不自动抹去前面有用的证据。仅合并旧 ID 或保留“曾展示”标记不够：当正文已经不在有效消息里，就不能只开放旧引用权限并假设模型还记得。这里先分析证据选择与消息组装职责，尚不决定具体保留算法或预算调整。

### 4.3 N03：先从准备缺口的语义与最终沿用入手

原问是考虑哪些未标注数据集。两套数据集名称及配对／未配对划分均答对；尚未证明附加句子与论文全文事实相反，问题是其证据范围不足以支撑那么强的全文排除表述，严重程度低于 N07 的关键事实漏答。

[原始 JSON](../../archive/run_logs/d9/agent_20261026_074712_634865_1bb13fd5d75e.json)显示，准备阶段的八条 facts 没有这句全文排除；它出现在 `missing_information` 中：“The paper does not name any separate, externally sourced non-annotated dataset…”。最终 claim 6 又把同一判断写为 analysis，并引用数据划分段。过强表述由准备缺口开始，不能只归于最终临时发挥。

切入点在于缺口描述究竟是在说明“原问还缺什么”，还是替论文补作“没有其他来源”的判断，以及最终如何使用这段缺口文字。已有材料足以回答两套数据及其未配对部分时，回答到这些有据事实即可，不必额外证明没有第三套数据。`analysis` 标签不会扩大证据所支持的范围，也不需要为此把整篇再读一遍以证明一个用户没问的排除结论。

RAGFlow 可参考的是忠实保留来源的范围、否定和不确定性，以及围绕用户问题作最小必要表达。该方向涉及准备与最终各自的职责，不要求新增全文否定检测、审核模型或事实校验器。
